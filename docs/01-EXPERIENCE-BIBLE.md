## 0. 本書について

### 0.1 本書の位置

```
L0  Project Constitution  ── 何をもって正しいとするか（判断の憲法）
      ↓
L1  Experience Bible（本書） ── どんな体験を届けるか（体験の定義）
      ↓
L2  各領域デザイン指針      ── ゲーム / UX / 猫AI / アート / サウンド / シナリオ
      ↓
L3  機能仕様書
      ↓
L4  実装
```

憲章が「してはいけないこと」を定めたのに対し、本書は**「何を届けるのか」**を定める。
憲章が守りなら、本書は攻めである。ただし攻めは常に守りの内側で行う。

### 0.2 本書で扱わないもの

- ゲームシステムの仕様（行動の種類、時間の刻み、判定式）
- UI設計（画面構成、ボタン配置、遷移）
- 猫AIの実装（行動決定アルゴリズム、パラメータ設計）
- アイテム・イベント・シナリオの中身
- アート仕様・サウンド仕様

これらは本書を**引用して**次工程で設計する。

### 0.3 三つのミッションの同時成立

本プロジェクトは、通常トレードオフになる3つを同時に成立させる。

| 軸 | 通常の解法 | 本作の解法 |
|---|---|---|
| **面白さ** | 報酬と成長曲線 | **解読の快感**（謎が解ける瞬間そのものが報酬） |
| **社会的価値** | メッセージの明示 | **体験の副産物**（言われずに、自分で気づく） |
| **教育** | 情報の提示と確認 | **仮説検証のサイクル**（学習方法そのものを体験させる） |

三者が衝突するのではなく、**同一の仕組みが三者を同時に満たす**構造にする。
これが本作の設計上の最大の賭けであり、Pillar 1〜3 がその実装である。

```
        観察 → 仮説 → 検証 → 理解
          │      │      │      │
面白さ ───┴──────┴──────┴──────┘  解読ゲームとしての快感
教育   ───┴──────┴──────┴──────┘  科学的思考の追体験
社会性 ───┴──────┴──────┴──────┘  他者理解の練習

         一つのループが、三つを同時に運ぶ
```

# ① Game Pillars — ゲーム体験の柱

> **目的**: 本作を本作たらしめる不可欠な7本を定義し、すべての実装判断の参照点にする。
> **背景**: 憲章§5の10原則は「判断基準」だが、抽象度が高く、日々の実装判断には粒度が粗い。原則を体験の言葉に翻訳する層が必要。
> **設計理由**: Pillarは「これを抜いたら別のゲームになる」ものだけに絞る。多すぎるPillarは優先順位を失わせ、少なすぎるPillarは判断の空白を生む。7本は、コアループ(3本)+時間軸(1本)+哲学(1本)+トーン(1本)+使命(1本)の最小構成である。
> **期待する効果**: 「これはPillar◯に反する」という一言で、根拠のある却下ができるようになる。
> **他章への影響**: ③④⑦⑧⑨は各Pillarの体験的帰結。⑫⑬はPillar違反の検出装置。

### Pillar 一覧

| # | 名前 | 一行定義 | 対応する憲章原則 |
|---|---|---|---|
| 1 | 見ることが、行為である | 観察が最も強い「プレイ」である | 原則7 |
| 2 | 答えではなく、手応えを渡す | 正解ではなく、確からしさが増える | 原則3・原則4・原則9 |
| 3 | 環境こそが、対話である | 唯一の発話手段は空間である | 原則8・原則2 |
| 4 | 30日は、戻らない | 不可逆な時間が体験に重みを与える | 原則1 |
| 5 | 変わるのは、猫ではない | 進行度はプレイヤー側にある | 原則10・原則5 |
| 6 | 静けさを、設計する | 何も起きない時間がコンテンツである | 原則6 |
| 7 | 現実へ続く、出口がある | ゲームの外側に接続される | Mission 1-3 |

## Pillar 1: 見ることが、行為である

### 名前
**Observation as Action** — 見ることが、行為である

### 目的
プレイヤーの主要な「動詞」を、操作ではなく**観察**にする。
他のゲームで「攻撃する」「移動する」が占める位置に、「見る」を置く。

### なぜ必要か

本作でプレイヤーが猫に対してできることは、極端に少ない。触れない、命令できない、育てられない。
この制約の中で「プレイしている感覚」を成立させる唯一の方法が、**観察を能動的な行為として設計すること**である。

観察が受動的なフレーバーに落ちた瞬間、本作は「猫を眺めるだけの退屈なゲーム」になる。
逆に観察が能動的な行為として立てば、本作は「情報を集めて謎を解くゲーム」として自立する。

さらに、観察を主行為に据えることは Mission そのものでもある。
**現実で猫と暮らすとき、人がすべきことも観察である。** ゲームの主行為と現実の正解が一致する、稀な構造を持てる。

### ゲーム体験への影響

- プレイヤーは「今日は何をしようか」ではなく「今日は何が違うか」と考えて1日を始める
- 「気づけた」ことが、それ自体で快感になる
- 見落としが、後から効いてくる（見なかった情報は永久に手に入らない）
- 熟練とは「速く操作できること」ではなく「多くを見つけられること」

### システム設計への影響

- **観察は低コスト・高頻度**。介入行動と違い、時間を消費させない、あるいは極めて安く済ませる
- **観察でしか得られない情報が必ず存在する**。テキストログや自動レポートで代替させない
- **観察対象は複層構造を持つ**：猫本体／痕跡／環境／時間帯／音
- **見なくても進行はする**。ただし見なかった分だけ、理解が浅いまま30日が終わる
- 見落としに対するペナルティは与えない。**得られなかっただけ**にする

### UIへの影響

- 猫が画面から消えない。あるいは、常に「猫を見に行く」導線が1操作以内にある
- **UIは猫を隠さない**。情報パネルが猫を覆う設計は却下
- クリック/タップして情報が「開く」のではなく、**見続けることで情報が「現れる」**
- 「観察モード」を特別なモードにしない。常時が観察である
- 何を見たかの記録は残るが、**何を見ていないかのチェックリストは出さない**（収集作業化するため）

### 演出への影響

- 重要な変化ほど**小さく**演出する。エフェクトで気づかせない
- 気づかせるための誘導は、光や矢印ではなく**猫の行動そのもの**で行う
- 音は情報である。画面外の音が観察を誘発する
- **同じ構図を繰り返し見せる**。差分が読めるのは、基準が身についているからである

### 実装時の注意点

- ⚠️ **最大の失敗モード**: 「気づいてもらえないから」とUIヒントを足し始めること。これはPillar 1の自殺である。気づかれないなら、演出の設計を直す。
- ⚠️ 観察の情報量が多すぎると、プレイヤーは見るのをやめる。**1日あたりの観測可能な情報は、記憶できる量に抑える**
- ⚠️ 観察を「全部見た」で埋められるコレクションにしない（憲章 §7.3）
- ⚠️ 自動で記録される情報と、プレイヤーが気づいて初めて記録される情報を、明確に分離する

## Pillar 2: 答えではなく、手応えを渡す

### 名前
**Confidence, not Correctness** — 答えではなく、手応えを渡す

### 目的
プレイヤーの仮説に対して、○×ではなく**「確からしさの変化」**を返す。
正解の宣告を排除し、推理の過程そのものを報酬にする。

### なぜ必要か

「答え合わせではなく理解する体験である」（憲章§3.4）を、体験レベルで実装する柱。

○×を返した瞬間、プレイヤーは考えるのをやめ、正解を探す作業に入る。
確からしさだけを返せば、プレイヤーは考え続ける。そして**考え続けている状態こそが、理解の実体**である。

また、猫という対象に対して「正解」を提示することは、事実として不誠実である。
猫の内心は誰にもわからない。わからないものをわからないまま扱うことが、原則2・原則5の誠実な実装になる。

### ゲーム体験への影響

- プレイヤーは常に「たぶん、こうだと思う」という状態で行動する
- 確信は徐々に高まるが、100%にはならない
- 「思った通りになった」ときの快感が、正解表示より強い（自分で確かめたから）
- 外れたときも、情報が増えている（次の仮説が具体的になる）

### システム設計への影響

- **仮説は明示的に立てられる**。ただし「提出して採点される」形式にしない
- 検証の結果は**現象で返す**。「仮説が正しかった」ではなく「猫がそうした／しなかった」
- 1回の結果で断定できない設計にする。**複数回の一致が確からしさを作る**
- 反証も情報として価値を持つ。外れた仮説を消さず、除外できた選択肢として残す
- 一つの現象に対し、**複数の妥当な解釈が併存できる**状態を許容する

### UIへの影響

- 正誤マーク（○×✓）を一切使わない
- 確信度を数値やゲージで表示しない。**言葉のニュアンス**で表す
  （「かもしれない」→「たぶん」→「この子はそうだ」）
- 仮説一覧は「未解決の問い」として並ぶ。**解決済み/未解決の進捗率は出さない**
- ノートの記述は断定形と推量形を使い分け、**確からしさを文体で示す**

### 演出への影響

- 「わかった瞬間」に効果音やカットインを付けない。**気づきは静かに訪れる**
- 代わりに、**世界の見え方を変える**：同じ仕草に、後半では違うテキストが添えられる
- 外れたときのリアクションを作らない。落胆の演出はプレイヤーを責めることになる

### 実装時の注意点

- ⚠️ 「わかりにくい」というテスト結果に対し、正解表示で解決しようとしない。**観察機会を増やす**か**現象を明確にする**で解決する
- ⚠️ 確からしさの表現に数値が混ざりやすい（「確度70%」等）。禁止。憲章 I-1
- ⚠️ 複数解釈の併存は実装が複雑になる。**すべての現象に複数解釈を用意する必要はない**。重要な問いに絞る
- ⚠️ プレイヤーが仮説を立てないまま進める抜け道を作らない。ただし強制もしない（強制はクイズ化する）

## Pillar 3: 環境こそが、対話である

### 名前
**Environment as Dialogue** — 環境こそが、対話である

### 目的
プレイヤーの唯一の「発話手段」を環境の変更にする。
猫に話しかけるのではなく、**空間で語りかける**。

### なぜ必要か

猫は命令に従わない（憲章 I-2）。ならばプレイヤーは何ができるのか。
答えは「猫が選べる選択肢を用意すること」である。

これは飼育の現実そのものでもある。猫を変えることはできないが、環境は変えられる。
そして環境を変えると、猫の行動が変わる。**これが猫との唯一の対話**であり、本作の中心的な相互作用になる。

「成長要素」を猫ではなく環境に置くこと（原則8）で、育成ゲームの快感構造を、倫理的に正しい形で獲得できる。

### ゲーム体験への影響

- プレイヤーは部屋を、猫の目線で見るようになる
- 「良い部屋」の定義が、プレイヤーの好みから**この猫にとっての快適さ**へ移行する
- 変更の効果は即座には出ない。**翌日以降に現れる**
- 良かれと思った変更が裏目に出る。それも対話である

### システム設計への影響

- 環境は**多次元**である：高さ／隠れ場所／動線／視線／音／光／匂い／温度／距離／時間帯
- 一つの物が**複数の意味**を持つ（段ボールは隠れ場所であり、障害物であり、爪とぎでもある）
- **正解の配置は存在しない**。個体ごとに最適解が異なる（原則2・原則3）
- 環境変更にはコストがかかる。ただし金銭ではなく**時間**と**猫への負荷**
- 変更そのものが猫にとってはストレス要因になりうる。**変えないことにも価値がある**

### UIへの影響

- 環境編集は「模様替え」の感覚。ゲーム的な装備画面にしない
- アイテムに性能値・効果説明を書かない（「警戒-10」のような表示は憲章 I-1 違反）
- 物の説明は**用途**ではなく**事実**で書く（「猫が好むタワー」ではなく「高さ120cm、上部に平らな面がある」）
- 猫視点で部屋を見る手段があると望ましい（次工程で検討）

### 演出への影響

- 環境変更の直後、猫は**警戒する**。良い変更でも、まず驚く
- 効果が現れるのは翌日以降。その「間」を演出として使う
- 猫が新しい場所を使い始める瞬間は、静かだが確実にわかる形で見せる
- 使われなかった物は、**そこにあり続ける**。無言の失敗として

### 実装時の注意点

- ⚠️ アイテム数を増やすことでコンテンツ量を稼ごうとしない（憲章 §14.2）。**1つの物の意味を増やす**
- ⚠️ 「高級品ほど効果が高い」構造は絶対に作らない。課金設計を呼び込み、原則8を破壊する
- ⚠️ 環境変更が万能の解法になると、観察（Pillar 1）が形骸化する。**環境で解けない問題も用意する**
- ⚠️ 模様替えの自由度は、楽しさとノイズの両面を持つ。自由度は「意味のある差」が出る範囲に限定する

## Pillar 4: 30日は、戻らない

### 名前
**Irreversible Thirty** — 30日は、戻らない

### 目的
時間の不可逆性によって、選択に重みを与える。
やり直しのなさが、**命を扱っている感覚**を生む。

### なぜ必要か

本作には勝敗もゲームオーバーもない（憲章 I-4）。緊張感の供給源が必要である。
その唯一の源が**時間の不可逆性**である。

同時にこれは、現実の写し身でもある。トライアル期間は実在する制度であり、猫の一生も戻らない。
「やり直せない」という感覚を持って初めて、プレイヤーは目の前の一日を真剣に見る。

ただし不可逆性は**焦燥に転化してはならない**（原則6）。ここが本Pillarの最大の設計難所である。

### ゲーム体験への影響

- 1日を終える操作に、わずかな躊躇が生まれる
- 「今日はもう少し見ておこう」という動機が生まれる
- 中盤で振り返ったとき、序盤の自分の未熟さが見える
- 30日目の決断が重い。軽く選べない

### システム設計への影響

- **セーブは自動・単一・上書き**。任意のロードによる巻き戻しを許さない
- **1日を確定する操作は明示的**。誤操作で進行しない（憲章 §9.5）
- 過去の記録は残る。**やり直せないが、参照はできる**
- 30日という長さは変更しない（憲章 §14.3）
- 周回は可能だが、**別の個体**である。同じ猫の再挑戦にしない

### UIへの影響

- 日付表示はする。ただし「残り◯日」を主表示にしない。**経過日数**を主にする
- カウントダウンの視覚的強調（赤字・点滅・音）は禁止
- 「セーブしますか？」を問わない。生活は勝手に進む
- 過去の日の記録へは、いつでも静かにアクセスできる

### 演出への影響

- 1日の終わりは、静かに、しかし明確に区切る
- 日付が変わる瞬間に、その日の重さを反映した「間」を置く
- 終盤に近づくほど、演出を**足すのではなく引く**（賑やかさで盛り上げない）
- 30日目の朝は、特別な演出をしない。ただの朝として始める。重さはプレイヤーの中にある

### 実装時の注意点

- ⚠️ **不可逆性と焦燥は紙一重**。「あと5日しかない」と思わせる表現を全レビューで検出する
- ⚠️ ブラウザゲームは中断・タブ閉じが日常的に起きる。**中断を「失敗」にしない**保存設計が必須
- ⚠️ セーブデータ破損は体験の全否定になる。技術的堅牢性は最優先事項として扱う
- ⚠️ 「やり直せない」がストレスになりすぎないよう、**取り返しのつかない致命的失敗は作らない**（Pillar 4 と ⑧ の両立点）

## Pillar 5: 変わるのは、猫ではない

### 名前
**The Player Is the Protagonist** — 変わるのは、猫ではない

### 目的
「成長」の所在をプレイヤー側に固定する。
猫の性格は本質的に変わらない。変わるのは、それを読むプレイヤーの目である。

### なぜ必要か

これは憲章§4.3の直接の実装であり、本作のアイデンティティそのものである。

多くのペット/育成ゲームは「相手が変わる」快感で駆動する。本作はそれを禁じている。
代わりに置くのが「**自分が変わった**」という快感である。これは達成感より深く、持続する。

そして本作のVision（プレイヤーの価値観が変わる）は、この構造でしか達成できない。
猫が変わるゲームでは、プレイヤーは何も持ち帰らない。

### ゲーム体験への影響

- 序盤に見た光景を終盤に再見すると、**意味が違って見える**
- プレイヤーは「猫が心を開いた」ではなく「わかるようになった」と語る
- 自分のノートの初期の記述が、後で読むと的外れに見える（成長の証拠）
- エンディングで問われるのは猫の状態ではなく、プレイヤーの理解

### システム設計への影響

- 猫の内部プロファイルは**基本的に固定**。警戒度などの状態は変動するが、性格は変わらない
- 進行の可視化は**プレイヤー側の資産**で行う：気づきの蓄積、記録、選べる観察の深さ
- **同一の現象に対する記述が、理解度に応じて変化する**仕組みを持つ（表現レイヤーでの実装）
- 猫の行動の「意味」はゲーム開始時から一貫している。後から追加されない

### UIへの影響

- 進捗表示は猫の欄ではなく、プレイヤーの欄（ノート）にある
- 「◯日目のあなたの記録」という形で、過去の自分を参照できる
- 猫のステータス画面という概念を作らない（憲章 I-1）

### 演出への影響

- **再解釈演出**が本Pillarの主武器：同じアニメーション、同じ構図、違うテキスト
- 終盤の「あの時、この子はこう思っていたのか」という気づきに最大の演出配分を置く
- 猫が変化したかのような演出（懐き演出、特別な仕草の解放）は行わない
  ※ 距離が縮まる等の**行動変化**は起きてよい。それは性格の変化ではなく状態の変化である

### 実装時の注意点

- ⚠️ **「猫が心を開いた」という誤読は自然に発生する**。テキストと演出で、それが「読めるようになった」ことだと繰り返し示す
- ⚠️ 状態変化（警戒→安心）と性格変化を混同しない。前者はあってよく、後者はない
- ⚠️ 再解釈演出はアセットの再利用で実現できる。コスト効率が高い。**序盤アセットは終盤で再利用する前提で作る**
- ⚠️ プレイヤーの成長を数値化したくなる誘惑が強い。理解度スコアは憲章 I-1 の精神に反する

## Pillar 6: 静けさを、設計する

### 名前
**Designed Silence** — 静けさを、設計する

### 目的
「何も起きない時間」を欠陥ではなく、意図されたコンテンツとして成立させる。

### なぜ必要か

本作の主題は待つことである（原則6）。にもかかわらず退屈を恐れて刺激を足せば、原則6は崩壊する。
「焦るほど悪循環になる」という体験は、**焦らないでいられる時間が用意されて初めて成立する**。

また、静けさは本作のトーンそのものであり、市場における差別化要因でもある。
賑やかなペットゲームは既に大量にある。静かなものは、ほとんどない。

### ゲーム体験への影響

- 猫が寝ているだけの時間に、耐えられる。むしろ心地よい
- 「何もしない」ことを選べる。それが後退ではないと感じられる
- プレイヤーの心拍が落ちる。呼吸が深くなる
- 小さな出来事が、大きな出来事に感じられる（コントラスト）

### システム設計への影響

- **「今日は何もしない」が常時選択可能**で、かつ有効な戦略である（憲章 §9.1 必達）
- 何も起きない日が存在してよい。すべての日にイベントを配置しない
- 時間の経過を、プレイヤーが能動的に「進める」のではなく、**眺めていられる**構造を検討する
- 通知・催促・リマインドを行わない

### UIへの影響

- 情報密度を低く保つ。画面の大半は余白か、部屋か、猫である
- 常時表示のUI要素は最小限。**画面占有率に上限を設ける**（憲章 §9.5）
- アニメーションするUI（点滅、脈動、バッジ）を使わない
- 待機画面・ロード画面も静けさの一部として設計する

### 演出への影響

- BGMを常時鳴らさない。**生活音と静寂が基本**（憲章 §9.6）
- 音楽が入る場面は限定し、そこを最大の感情ピークにする
- カメラは動かない。固定構図が基本
- テキストで間を埋めない。無言の時間を許す

### 実装時の注意点

- ⚠️ **プレイテストで必ず「退屈」というフィードバックが出る**。それが即座に「刺激を足せ」を意味しない。退屈と静けさを区別する指標を持つ（⑬参照）
- ⚠️ 静けさの中では、小さなノイズが目立つ。音・アニメーションの品質基準は逆に高くなる
- ⚠️ ブラウザゲームは離脱が容易。静けさが離脱を招かないよう、**次の観察対象**を常に一つ残しておく
- ⚠️ 「静か」と「情報がない」は違う。静かな画面にも、読み取れるものは常に存在させる

## Pillar 7: 現実へ続く、出口がある

### 名前
**The Door to Reality** — 現実へ続く、出口がある

### 目的
ゲーム体験を、現実の行動・意識変容へ接続する。
Mission 1〜3 の達成装置であり、本作の社会的価値の実体。

### なぜ必要か

本作の成功条件は「プレイヤーの価値観が少し変わっていること」である（憲章 §11.1）。
価値観の変化は、ゲームの内側だけでは完結しない。**外側への接続点**が設計されて初めて成立する。

ただしこれは最も**押し付けに転びやすい**Pillarである。
説教になった瞬間、プレイヤーは反発し、Mission 4（押し付けない）に違反する。

### ゲーム体験への影響

- ゲーム内の知識が、現実の猫にも当てはまることに気づく
- 「自分にもできそう」という感覚が芽生える（あるいは「今の自分には難しい」という正直な自覚）
- エンディング後、自分で調べたくなる
- 街で猫を見たとき、見方が変わっている

### システム設計への影響

- ゲーム内の知識は**すべて現実に基づく**（憲章 §9.2）。ゲーム独自の嘘の設定を作らない
- 譲渡の手続き・条件・トライアル制度は、現実に即して描く
- 現実情報への導線は**ゲーム終了後**に置く。プレイ中は提示しない
- 導線は**任意**である。無視して閉じられる

### UIへの影響

- 現実情報は明確に「ゲームの外」とわかる意匠にする（ゲーム内UIと混ぜない）
- ボタンではなく、静かなリンクとして提示する
- 押さずに閉じることが、何のペナルティにもならない

### 演出への影響

- エンディング直後に情報を出さない。**余韻を挟む**
- 感動の直後に行動を促さない（感情操作になる）
- トーンは勧誘ではなく、**情報提供**

### 実装時の注意点

- ⚠️ **最大の危険**: 感動的なエンディング → 即座に「保護猫を迎えよう」の導線。これは感情操作であり、憲章 I-10 の精神に反する
- ⚠️ 寄付・支援の導線を、感動の直後に置かない
- ⚠️ 現実情報は陳腐化する。**外部情報は更新可能な形で分離**して持つ
- ⚠️ 「迎えない」選択をした人を否定しない。迎えないことも尊重される選択である
- ⚠️ 特定団体との提携は、憲章 I-8（中立性）との整合を個別に検証する

# ② Core Fantasy

> **目的**: プレイヤーが「何者として」「何を体験するか」を定義し、全表現の一人称視点を統一する。
> **背景**: 一般的なゲームは「なりたい自分」を提供する（勇者、王、englishマスター）。本作が提供するのは能力の獲得ではなく**感覚の獲得**であり、既存の類型に当てはまらない。独自の言語化が必要。
> **設計理由**: Fantasyが曖昧だと、シナリオは「飼い主目線」に、UIは「管理者目線」に、演出は「観客目線」に散る。一人称を固定することが、全領域の一貫性の土台になる。
> **期待する効果**: あらゆるテキスト・演出・UIが「この立場の人間が見ている光景か」で検証可能になる。
> **他章への影響**: ③の感情はこのFantasyの内側で起きる。⑨の成長はこのFantasyの深化である。⑤⑫はFantasyを壊す要素の排除リスト。

## 2.1 プレイヤーは何者か

> ### **まだ飼い主ではない、一人の人間。**

| 項目 | 定義 |
|---|---|
| **立場** | 保護猫のトライアル期間中の、譲渡希望者 |
| **持っている権限** | 自分の部屋を変えること。自分の振る舞いを変えること。時間の使い方を決めること |
| **持っていない権限** | 猫の感情。猫の行動。猫の過去。猫を迎えるかどうかの最終的な正しさ |
| **持っている武器** | 目。時間。想像力 |
| **持っていない武器** | 言葉。力。専門知識（最初は） |
| **抱えているもの** | 「自分にこの子を幸せにできるのか」という問い |

### 「まだ」であることの重要性

プレイヤーは飼い主ではない。**候補**である。
この不確定性が、本作のすべての緊張と誠実さを生む。

- 飼い主なら「うまくやる」が目標になる → 攻略ゲームになる
- 候補なら「見極める」が目標になる → 観察ゲームになる

同時に、猫の側も**まだこの家の猫ではない**。
互いに「これから決まる」関係であり、そこに上下はない。

## 2.2 Core Fantasy 本体

> ### **「言葉の通じない相手の世界が、少しずつ読めるようになっていく」**

これが本作の中核体験である。

これは能力の獲得ファンタジーではなく、**知覚の変容ファンタジー**である。
プレイヤーは強くならない。**目が変わる**。

### 分解すると

```
最初:  猫が、何を考えているかわからない生き物に見える
         ↓
中盤:  猫の行動に、規則があることに気づく
         ↓
終盤:  同じ光景を見て、意味が読み取れる
         ↓
最後:  「この子は今、こう感じている」と、根拠を持って言える
```

**この過程が、外国語が読めるようになる感覚に極めて近い。**
最初はただの模様だった文字が、ある日、意味を持って立ち上がる瞬間。

本作が提供するのは、その瞬間である。

## 2.3 サブ・ファンタジー

Core Fantasyを支える3つの副次的な快感。

| # | ファンタジー | 快感の正体 | 対応Pillar |
|---|---|---|---|
| **SF-1** | **探偵になる** | 断片的な手がかりから、見えないものを推理する | P1・P2 |
| **SF-2** | **場を整える人になる** | 誰かのために空間を作り、それが使われる | P3 |
| **SF-3** | **信頼される** | 求めていないのに、向こうから近づいてくる | P5 |

### 各サブ・ファンタジーの扱い

**SF-1 探偵になる（主軸）**
本作のゲーム性の大半はここに宿る。証拠（痕跡）、証言（行動）、推理（仮説）、検証（環境変更）という探偵小説の構造をそのまま使える。
ただし**犯人はいない**。解くべきは事件ではなく、一つの生き物の内側である。

**SF-2 場を整える人になる（支軸）**
「自分の作った空間が使われる」快感は、建築・箱庭ゲームが持つ普遍的な喜びである。
本作ではこれを**自己表現ではなく他者への配慮**として設計する。おしゃれな部屋ではなく、この子が安心できる部屋。

**SF-3 信頼される（副産物）**
最も強い快感だが、**これを目標にした瞬間に本作は崩壊する**。
懐かせることを目的化すると、猫が攻略対象になる（憲章 I-2・原則10 違反）。

したがって SF-3 は：
- **報酬として設計しない**
- **目標として提示しない**
- **起きたときに、その理由が理解できる形で起こす**

> 「懐いた」ことが嬉しいのではない。**なぜ懐いたのかがわかった**ことが嬉しい。

## 2.4 本作が提供しないファンタジー

| 提供しないもの | 理由 |
|---|---|
| 強くなる | 能力の成長は本作に存在しない（憲章 I-3） |
| 支配する / 従わせる | 憲章 I-2 |
| 完璧な飼い主になる | 完璧は存在しない。誠実さだけがある |
| 猫に愛される | 愛を報酬にすると、猫が手段になる |
| 救う / 助ける | 救済者の視点は、猫を弱者として固定する。対等ではない |
| 集める / 揃える | 収集は理解の対義語（憲章 I-7） |

### 特に注意：「救う」ファンタジーの危険性

保護猫という題材は、容易に「救済者ファンタジー」に転ぶ。
「かわいそうな猫を、私が救う」——この構図は、Mission 3（偏見をなくす）に真っ向から反する。

保護猫は救われる対象ではなく、**一緒に暮らす相手**である。
本作のFantasyは「救う」ではなく「**わかる**」である。この違いを全領域で徹底する。

## 2.5 Fantasy 検証テスト

新しい要素がCore Fantasyに適合するか、以下で判定する。

```
□ この要素は「読めるようになる」感覚に貢献するか
□ プレイヤーは「まだ飼い主ではない人」の立場に留まっているか
□ 猫が「理解の対象」であり続けているか（攻略対象・救済対象になっていないか）
□ プレイヤーの能力ではなく、知覚が変わる方向に働くか
□ 「救う」ではなく「わかる」の側にあるか
```

# ③ Core Emotional Journey

> **目的**: 30日間のプレイヤー感情を段階設計し、各段階で「感じるべきこと・学ぶべきこと・見せるべきもの」を確定する。
> **背景**: 憲章§8.2で大枠の感情曲線を定義済み。本章はそれを実装可能な粒度まで分解し、演出・シナリオ・システムの配置指針とする。
> **設計理由**: 感情設計を先に固定しないと、イベントは「面白そうだから」で配置され、曲線が崩れる。感情の順序は学習の順序でもあるため、崩れると教育設計も破綻する。
> **期待する効果**: 「Day 15にこの演出を入れてよいか」という判断が、感情段階との整合で機械的に判断できる。
> **他章への影響**: ⑥の学習段階は本章と同期する。⑪の感情的報酬は各段階に配分される。⑩は Phase 7 の設計。

## 3.1 感情曲線の全体像

   │                                        ╭─────╯

   │                      ╭───╮ ╭─────╯
   │                ╭─────╯   ╰─╯ ⑤ 理解・読解
   │          ╭─────╯ ④ 停滞・揺り戻し
   │    ╭─────╯ ③ 発見・興味
   │╭───╯ ② 無力感・不安

## Phase ① 期待と気負い（Day 0）

| 項目 | 内容 |
|---|---|
| **感じるべきこと** | これから始まるという高揚。少しの緊張。「良い飼い主になろう」という前のめりな意欲 |
| **感じてはいけないこと** | 義務感。プレッシャー。ルール説明への退屈 |
| **学ぶべきこと** | （まだ何も学ばせない）状況の理解のみ：トライアルとは何か、30日とは何か |
| **見せるべきもの** | 空の部屋。これから猫が来るという事実。プレイヤー自身の生活の気配 |
| **見せてはいけないもの** | 猫の生態解説。操作チュートリアル。目標の提示 |
| **演出の方針** | 静かな期待。生活音。準備の手触り |

### 設計上の要点

**この段階でプレイヤーは「気負っている」のが正しい。**
そしてその気負いが、Phase ② で折られることが設計意図である。

「うまくやろう」という前のめりな態度は、現実の里親候補の多くが持つものであり、
それが通用しないことを体験することが、本作の最初の学習になる。

チュートリアルは行わない。行うのは**状況説明のみ**。
「何をすればいいか」を教えない。それを見つけることがゲームだからである。

## Phase ② 無力感と不安（Day 1-5）

| 項目 | 内容 |
|---|---|
| **感じるべきこと** | 「何もできない」という無力感。猫が見えないことへの不安。それでも気になる |
| **感じてはいけないこと** | 「このゲームは壊れている」という不信。「詰んだ」という絶望。放置してよいという諦め |
| **学ぶべきこと** | ・猫はすぐには出てこない<br>・待つことに意味がある<br>・見えなくても情報はある（痕跡） |
| **見せるべきもの** | ・隠れている猫（あるいは、猫の一部だけ）<br>・減った餌、使われたトイレ、動いた物<br>・夜間の物音 |
| **見せてはいけないもの** | 猫の内心。「猫は今、怖がっています」という説明。焦りを煽る表示 |
| **演出の方針** | 静寂。広く感じる部屋。プレイヤーの気配に反応して隠れる猫 |

### 設計上の要点

**この段階の設計難易度が最も高い。** 離脱率が最大になる期間である。

無力感は必要だが、**無力感と「何も起きない」は違う**。
猫は見えなくても、**変化は毎日起きている必要がある**。

```
Day 1: 猫は姿を見せない。餌は減っていない
Day 2: 餌が少し減っている。夜、物音がした
Day 3: 猫の一部が見えた（尻尾だけ、目だけ）
Day 4: 昼間に一度、移動した痕跡
Day 5: 短時間だけ、姿が見えた。目が合ったら隠れた
```

**「何もできない」が「何も観測できない」にならないこと。**
これがPhase ②の必達条件である。

Phase ①の気負いが折られる瞬間（近づいたら逃げられる等）を、Day 2-3 に必ず配置する。

## Phase ③ 発見と興味（Day 6-12）

| 項目 | 内容 |
|---|---|
| **感じるべきこと** | 「あ、そうか」という発見。仮説が当たったときの手応え。もっと知りたいという興味 |
| **感じてはいけないこと** | 「攻略できた」という征服感。「もうわかった」という慢心 |
| **学ぶべきこと** | ・猫の行動には理由がある<br>・環境を変えると反応が変わる<br>・観察の対象は猫だけではない（時間帯、音、動線） |
| **見せるべきもの** | ・行動の規則性（毎日同じ時間に同じ場所）<br>・環境変更への反応<br>・最初の「近づいてきた」瞬間 |
| **見せてはいけないもの** | 正解の宣告。「その通り！」という肯定。急激な関係改善 |
| **演出の方針** | 小さな変化を確実に。効果音で祝わない。プレイヤーが自分で気づく余地を残す |

### 設計上の要点

**本作で最初に「面白い」と感じる期間。** ここで掴めなければ完走されない。

ただし、**手応えを与えすぎない**。
Phase ③で「わかった」と思わせすぎると、Phase ④の落差が理不尽に感じられる。

正しい設計は「**部分的に通用する仮説**」を与えること。
- 「この子は物音に敏感だ」→ 正しい。だが物音のすべてではない
- 「高い場所が好き」→ 正しい。だが、いつでもではない

**この段階の仮説は、後に「もっと正確な仮説」に更新される必要がある。**
それがPhase ④の役割である。

## Phase ④ 戸惑いと停滞（Day 13-20）

| 項目 | 内容 |
|---|---|
| **感じるべきこと** | 「わからなくなった」という戸惑い。うまくいかない悔しさ。自分のやり方への疑い |
| **感じてはいけないこと** | 理不尽さ。「ゲームが意地悪をしている」という感覚。自己嫌悪。諦め |
| **学ぶべきこと** | ・単純な法則では説明できない<br>・自分の仮説が粗かった<br>・焦って介入すると悪化する<br>・待つことは後退ではない |
| **見せるべきもの** | ・仮説が通用しない事例<br>・過干渉による明確な後退<br>・何もしなかった日の、静かな回復 |
| **見せてはいけないもの** | プレイヤーを責めるテキスト。「あなたのせいです」。理由不明の不調 |
| **演出の方針** | 後退を、責めずに、しかし明確に見せる。距離が開く。使っていた場所を使わなくなる |

### 設計上の要点

**本作の心臓部。ここが成立すれば作品として成立する。**

Phase ④は「難易度が上がる」のではなく「**理解の解像度が足りないことが露呈する**」段階である。

#### 必ず起こすべき2つの体験

**体験A: 過干渉の失敗**
プレイヤーが良かれと思って積極的に介入し、猫が明確に後退する。
これは原則6（焦るほど悪循環になる）の体験的証明であり、本作最重要の学習である。

**体験B: 何もしないことの効果**
プレイヤーが手を止め、待った結果、猫の側から動きが出る。
これが体験Aの直後に来ることで、対比が最大化する。

```
Day 13-16  介入を強める → 猫が後退する（悪循環）
Day 17-18  行き詰まる → 手を止める
Day 19-20  猫が、自分から動く
```

#### 理不尽と難しさの境界線

Phase ④で最も危険なのは、プレイヤーが「理不尽だ」と感じることである。
境界線は**事後の説明可能性**にある。

```
❌ 理不尽 : なぜ悪化したか、後から考えてもわからない
✅ 難しい : なぜ悪化したか、後から考えると納得できる
```

したがって、**すべての後退には、観察可能な原因が先行していなければならない**。
プレイヤーが見落としただけで、情報は必ず提示されていること。

## Phase ⑤ 理解と安心（Day 21-27）

| 項目 | 内容 |
|---|---|
| **感じるべきこと** | 「読める」という静かな確信。安心。猫と同じ空間にいる心地よさ |
| **感じてはいけないこと** | 「クリアした」という達成感。優越感。猫を掌握したという感覚 |
| **学ぶべきこと** | ・自分の見る目が変わったこと<br>・同じ行動が、状況で違う意味を持つこと<br>・完全には理解できないこと |
| **見せるべきもの** | ・**序盤と同じ光景の、違う意味**（再解釈演出）<br>・猫の側から近づいてくる<br>・二人が同じ部屋で、別々のことをしている時間 |
| **見せてはいけないもの** | 劇的な和解。ファンファーレ。「懐きました」の宣言 |
| **演出の方針** | 本作最大の演出配分。ただし派手にではなく、深く。音楽を許す唯一の期間 |

### 設計上の要点

**Pillar 5 の収穫期。** ここで「変わったのは自分だ」と気づかせる。

#### 再解釈演出の設計

Phase ⑤の主武器は、**序盤アセットの再利用による意味の反転**である。

| 序盤（Day 2） | 終盤（Day 24） |
|---|---|
| 同じアニメーション | 同じアニメーション |
| 「猫が、こちらを見ている」 | 「こちらを見ている。ここに居ていいか、確かめている」 |
| 意味がわからない | 意味がわかる |

**アニメーションは同一。テキストと文脈だけが変わる。**
これによりプレイヤーは、変わったのが猫ではなく自分だと直感的に理解する。

#### 感情ピークの配置

憲章§8.1で定義した最大ピーク——
> **猫が近づいてきた瞬間ではなく、「なぜ近づいてきたのか」がわかった瞬間**

は、Phase ⑤ に配置する。

配置順序は必ず：
```
1. 猫が近づいてくる（現象）
2. プレイヤーが「なぜ」と思う
3. 過去の観察と結びつく
4. 理解が訪れる  ← ここが最大ピーク
```

現象と理解を同時に起こさない。**間に「なぜ」を挟む**。

## Phase ⑥ 決断と責任（Day 28-30）

| 項目 | 内容 |
|---|---|
| **感じるべきこと** | 責任の重み。決めるのは自分だという自覚。少しの寂しさ |
| **感じてはいけないこと** | 誘導されている感覚。正解を選ばされている感覚。罪悪感 |
| **学ぶべきこと** | ・迎えることは、生活が変わること<br>・迎えないことも、誠実な判断でありうること<br>・判断材料は、自分が集めた観察である |
| **見せるべきもの** | ・現実的な情報（費用、時間、生活の変化）<br>・30日間の自分の記録<br>・猫の、変わらない日常 |
| **見せてはいけないもの** | 感動的な別れの演出。涙を誘う音楽。「選んでください」の圧 |
| **演出の方針** | **引く**。特別な演出をしない。30日目も、ただの朝として始める |

### 設計上の要点

#### 決断の設計原則

```
□ 選択肢に優劣を示唆しない
□ 選択前に、判断材料を過不足なく提示する
□ 選択後に、結果の良し悪しを評価しない
□ どの選択も、プレイヤーが「考え抜いた結果」として扱う
```

#### 三つの結末（憲章§6.6）

| 結末 | 意味 | 描き方 |
|---|---|---|
| **正式譲渡** | この子と暮らしていける確信を得た | 喜びではなく、責任の始まりとして |
| **トライアル延長** | まだわからない。急がない | 逃げではなく、誠実な保留として |
| **見送り** | この環境では幸せにできない | 失敗ではなく、猫のための判断として |

**「見送り」を選んだプレイヤーが自分を責めることは、設計の失敗である**（憲章 §11.3）。
見送りエンディングでは、明示的に「その判断も猫のためである」ことを、説教にならない形で伝える。

#### 感動の押し売り禁止

Day 30 で泣かせにいかない。
本作の情動は、**プレイヤーの内側から自発的に立ち上がるもの**であって、演出で引き出すものではない。

音楽・スローモーション・回想モンタージュといった「感動の記号」は、
Phase ⑥ ではむしろ**使わない**ほうが強く働く。

# ④ Core Motivation

> **目的**: 外的報酬に頼らず、プレイヤーが翌日も遊びたくなる心理的駆動力を設計する。
> **背景**: 憲章 I-5・I-7 により、ログインボーナス・スタミナ・実績解放といった一般的な継続動機はすべて使用不可。代替を明示的に設計する必要がある。
> **設計理由**: 動機設計を空白にすると、離脱率の悪化に対して「デイリー報酬を入れよう」という圧力が必ず生じる。先に代替案を用意しておくことが、憲章を守る最良の方法である。
> **期待する効果**: 「継続率が低い」という問題に対し、憲章違反でない打ち手のリストが即座に参照できる。
> **他章への影響**: ⑪の感情的報酬は本章の実装形。⑫は使用禁止の動機づけリスト。

## 4.1 動機の基本構造

本作の継続動機は、**未完了の問い**によって駆動される。

```
今日、疑問が生まれる
   ↓
今日のうちには答えが出ない（1日=1回の検証しかできない）
   ↓
「明日どうなるか見たい」
   ↓
翌日、結果が出る
   ↓
新しい疑問が生まれる  ← ループ
```

**報酬が明日あるのではない。答えが明日あるのである。**

## 4.2 五つの心理的動機

| # | 動機 | 心理機構 | 発生タイミング |
|---|---|---|---|
| **M1** | 未完了の問い | ツァイガルニク効果 | 全期間・毎日 |
| **M2** | 解読の快感 | 認知的閉合・洞察の喜び | Phase ③⑤ |
| **M3** | 関係の兆し | 相互性の知覚 | Phase ③⑤ |
| **M4** | 自己変化の実感 | 有能感・自己効力感 | Phase ⑤⑥ |
| **M5** | 不可逆性の重み | 損失回避・希少性 | 全期間・特に終盤 |

---

### M1: 未完了の問い（主動機）

**心理機構**: 人は完結していない事柄を、完結した事柄より強く記憶し、気にかける（ツァイガルニク効果）。

**設計要件**
- 1日の終わりに、**必ず未解決の問いが1つ以上残る**
- 昨日の行動の結果は、**翌日に現れる**（即時フィードバックにしない）
- 問いは自然発生的であるべきで、「明日の予告」として提示しない

**やってはいけない実装**
- 「明日、◯◯が起きます」という予告（結果を先に知らせる）
- 「未解決の謎: 3件」というカウンター表示（タスク化する）

**やるべき実装**
- 環境を変えた翌日に反応が出る構造
- 日をまたぐ行動パターンの存在（3日周期など）
- 見えなかったもの、確かめきれなかったことが残る設計

---

### M2: 解読の快感

**心理機構**: 断片が繋がって意味をなす瞬間の快感（Aha体験）。人為的な報酬より強く、記憶に残る。

**設計要件**
- 情報を**分散して配置**する。1箇所で完結させない
- 過去の観察が、後になって意味を持つ構造
- プレイヤーが自力で繋げる余地を残す（繋げてあげない）

**強度の設計**
Aha体験の強度は「繋がるまでの距離」に比例する。
Day 3 の観察が Day 22 に意味を持つ——この距離が、快感の大きさを決める。

したがって**序盤に、意味がわからないまま提示される情報**を意図的に配置する。

---

### M3: 関係の兆し

**心理機構**: 相手が自分に反応しているという知覚。社会的報酬の一種。

**設計要件**
- 変化は**小さく、確実に**。劇的にしない
- 変化はプレイヤーの行動と因果で結ばれる（無関係に起きない）
- ただし、**それを目標として提示しない**（SF-3の扱いに準拠）

**注意**
これは最も強力だが、最も危険な動機である。
「懐かせるゲーム」に転落する引力が常に働く。

安全弁：
```
関係の変化を、進捗として可視化しない
関係の変化を、報酬として演出しない
関係の変化の「理由」を、常にセットで理解可能にする
```

---

### M4: 自己変化の実感

**心理機構**: 有能感（自分が上達している感覚）は、内発的動機の三大要素の一つ。

**設計要件**
- 過去の自分の記録が読み返せる（拙さが見える）
- 同じ現象に対する自分の解釈が深まっていることが見える
- 上達を**数値で示さない**（憲章 I-1）。文体と内容の変化で示す

**実装のヒント**
「Day 3 のあなたの記録」を Day 20 に読むと、素朴すぎて少し恥ずかしい。
この感覚が、最も純度の高い成長実感である。

---

### M5: 不可逆性の重み

**心理機構**: 二度と手に入らないものへの注意集中（希少性）。

**設計要件**
- 1日は戻らない（Pillar 4）
- 見なかったものは、見られない
- ただし**焦燥に転化させない**（原則6）

**焦燥と重みの境界**

```
❌ 焦燥 : 「早くしないと間に合わない」→ 急がせる
✅ 重み : 「今日という日は今日しかない」→ 丁寧にさせる
```

表現の差：
- ❌「残り5日」を大きく表示
- ✅「Day 25」と静かに表示。日記に「あと少しだ」と書かれる程度

## 4.4 離脱対策の許容手段

継続率が問題になった場合、以下の順で対処する。**上から試す**。

```
1. Phase ② の観測可能情報を増やす（無力感 ≠ 無情報）
2. 1日の所要時間を短くする（1〜2分の厳守）
3. 中断・再開の摩擦を減らす（ロード時間、再開位置）
4. 「明日への問い」の明確さを上げる
5. 序盤の Aha 体験を前倒しする（Day 6 → Day 4 等）
6. 冒頭の状況説明を短くする
```

**この6つで解決しない場合、体験設計そのものを見直す。**
報酬の追加で解決しようとした時点で、本作は別のゲームになる。

# ⑤ Player Experience Principles

> **目的**: プレイヤーが感じるべき感情・感じてはならない感情を一覧化し、体験の合否を判定可能にする。

> **期待する効果**: プレイテスト設計・フィードバック分類・改修方針決定が高速化する。
> **他章への影響**: ③の各Phaseの検証基準。⑬チェックリストD群の根拠。

### N-14「退屈」の特別な扱い

**「退屈」と「静か」は違う。両者を混同した対処が、本作を最も損なう。**

| | 静か（正しい） | 退屈（誤り） |
|---|---|---|
| 観測できるもの | ある（見れば読める） | ない |
| プレイヤーの状態 | 見入っている | 早く進めたい |
| 次の行動 | 考えている | わからない |
| 対処 | **不要** | 観測対象を増やす |

**判定方法**: プレイテストで「今、画面に何が見えますか」と聞く。
答えられる → 静か。答えられない → 退屈。

「退屈」への対処として**刺激・報酬・演出を足すことは禁止**。
足すのは常に**観測できるもの**である。

| 感情 | 許容される条件 | 禁止される条件 |
|---|---|---|
| **もどかしさ** | 次にやることが見えている | 何をすればいいかわからない |
| **不安** | 猫への心配として | ゲームの不具合への疑い |
| **寂しさ** | 別れの実感として | 見捨てられ感として |
| **悔しさ** | 自分の観察不足への自覚 | ゲームへの不満 |
| **無力感** | Phase ② の設計された無力感 | 全期間にわたる無力感 |
| **緊張** | 決断の重みとして | 時間切れへの焦りとして |

# ⑥ Learning Experience

> **目的**: 知識の伝達ではなく、理解の生成を起こす学習設計を確立する。
> **背景**: 憲章§7で提示順序と禁則を定義済み。本章はその上に、学習の構造モデル・理解の定着方法・転移設計を積む。
> **設計理由**: 教育を目的に掲げるゲームの大半は「情報の提示＋確認テスト」に落ちる。これを避けるには、学習理論に基づく明示的な設計が要る。
> **期待する効果**: シナリオ・ノート・演出が「どの学習段階を担うか」で設計・検証できる。
> **他章への影響**: ③のPhaseと同期。⑦の観察設計は学習の入力側。⑨の成長は学習の出力側。

## 6.1 知識と理解の違い（再定義）

| | 知識 | 理解 |
|---|---|---|
| 形式 | 命題（「猫は〜である」） | モデル（「この状況ではこうなる」） |
| 獲得方法 | 提示される | 構築される |
| 検証方法 | 想起できるか | 未知の状況に適用できるか |
| 忘却 | 早い | 遅い |
| 転移 | しない | する |
| 本作での扱い | **手段** | **目的** |

**本作の学習目標は「転移する理解」である。**
すなわち、ゲーム内の猫Aで学んだことが、猫B、そして現実の猫に適用できること。

## 6.2 三層学習モデル

本作の学習は3つの層で構成される。

```
┌───────────────────────────────────────────┐
│ 第3層: 一般化層                            │
│   「猫は、安心できない場所では食べない」    │  ← 転移可能
│   ※ ゲーム外に持ち出せる                   │
└───────────────▲───────────────────────────┘
                │ 複数事例の統合
┌───────────────┴───────────────────────────┐
│ 第2層: 解釈層                              │
│   「この子は、人の動線上では食べない」      │  ← 個体理解
│   ※ この猫に固有                           │
└───────────────▲───────────────────────────┘
                │ 仮説と検証
┌───────────────┴───────────────────────────┐
│ 第1層: 現象層                              │
│   「食器の前まで来て、食べずに戻った」      │  ← 観察事実
│   ※ 解釈を含まない                          │
└───────────────────────────────────────────┘
```

### 各層の設計ルール

| 層 | 誰が生成するか | ゲームが提供するもの | 禁止事項 |
|---|---|---|---|
| **第1層 現象** | ゲーム | 観測可能な事実のみ | 解釈を混ぜない |
| **第2層 解釈** | **プレイヤー** | 仮説を立てる手段 | 解釈を代行しない |
| **第3層 一般化** | プレイヤー＋ゲーム | 言語化の補助 | 先に提示しない |

**最重要ルール: 第2層はプレイヤーが埋める。ゲームは絶対に代行しない。**

第2層をゲームが埋めた瞬間、学習は「知識の受け取り」に退化する。
ゲームが提供してよいのは、第1層（事実）と、第3層への言語化補助のみ。

## 6.3 学習サイクル（憲章§7.2の詳細化）

```
[1] 遭遇      現象に出会う                    ゲームが提供
      ↓
[2] 違和感    「あれ？」                      プレイヤーの内側で発生
      ↓
[3] 疑問化    「なぜだろう」                  ゲームが場を用意（ノート）
      ↓
[4] 仮説      「たぶん〜だから」              プレイヤーが生成
      ↓
[5] 予測      「なら、〜すればこうなるはず」  プレイヤーが生成
      ↓
[6] 検証      環境を変える／待つ              ゲームが手段を提供
      ↓
[7] 観測      結果を見る                      ゲームが現象で返す
      ↓
[8] 更新      仮説を修正／強化                プレイヤーが実行
      ↓
[9] 言語化    ノートに残る                    ゲームが補助
      ↓
[10] 一般化   別の場面でも通用する            ゲームが機会を提供
      ↓
    （[1] へ）
```

### 段階ごとの支援設計

| 段階 | プレイヤーが詰まる原因 | 許容される支援 | 禁止される支援 |
|---|---|---|---|
| [2] 違和感 | 変化に気づかない | 現象の明確化・反復 | 「注目！」の表示 |
| [4] 仮説 | 何を考えればいいかわからない | 問いの形の提示 | 選択肢としての正解提示 |
| [6] 検証 | 手段が思いつかない | 使える手段の可視化 | 「これを使いましょう」 |
| [8] 更新 | 結果の意味がわからない | 現象の再提示 | 解釈の提供 |
| [10] 一般化 | 別場面と結びつかない | 類似状況の配置 | 「前と同じですね」 |

## 6.4 「教えない」ための四つの技法

### 技法1: 現象先行（Phenomenon First）

必ず**見せてから**、言葉を与える。逆はしない。

```
❌ 「猫は高い所を好みます」→ 猫が棚に登る
✅ 猫が棚に登る → プレイヤーが気づく → ノートに言葉が生まれる
```

### 技法2: 不完全な言語化（Incomplete Articulation）

ノートに書かれる言葉は、**完成した知識ではなく、途中の思考**として書く。

```
❌ 「猫は視線を合わせられることを威嚇と感じる」
✅ 「目が合うと逃げる。まっすぐ見ないほうがいいのかも」
```

不完全さが、プレイヤーに「考える余地」を残す。

### 技法3: 反例の配置（Counterexample Placement）

法則を教えた後ではなく、**プレイヤーが法則を掴んだ頃に、例外を出す**。

これが Phase ④ の設計そのものである。
反例に出会うことで、理解は「単純な法則」から「文脈依存のモデル」へ深化する。

### 技法4: 遅延した意味（Delayed Meaning）

序盤に、**意味がわからないまま提示される情報**を置く。
終盤に、それが意味を持つ。

```
Day 2:  猫が、餌を食べる前に必ず一度、部屋を見回す
        （プレイヤーは意味がわからない）
        ↓
Day 24: 安心できていない場所では、周囲を確認してからでないと食べない
        （Day 2 の記憶が、意味を持つ）
```

これは M2（解読の快感）の実装でもある。

## 6.5 誤解の扱い

プレイヤーは必ず誤解する。**誤解は学習の一部であり、修正されるべきものであって、罰されるべきものではない。**

| 誤解の種類 | 扱い |
|---|---|
| **一時的な誤解** | 放置してよい。後の反例で自然に修正される |
| **有用な誤解** | 部分的に正しいもの。修正せず、精緻化させる |
| **有害な誤解** | 現実の猫に危険が及ぶもの。**必ず修正する**（下記） |

### 有害な誤解の修正

現実の飼育において危険な誤解（例：ネギ類を与えてよい、放し飼いは自由でよい、等）は、
ゲーム内で放置してはならない。ただし修正方法は憲章に従う。

```
❌ 警告ダイアログ「それは危険です！」
❌ 「間違っています」というテキスト
✅ 現象として明確な悪化を見せる（ただし過度に悲惨にしない）
✅ ノートに、プレイヤー自身の反省として言語化される
✅ ゲーム外の情報層（Reality Bridge）で正確な情報を提供する
```

## 6.6 学習内容の範囲

| 扱う | 扱わない |
|---|---|
| 猫の行動の意味（ボディランゲージ、行動学） | 詳細な医学知識 |
| 環境エンリッチメントの考え方 | 特定商品の推奨 |
| 個体差という概念 | 品種ごとの特性の断定 |
| 譲渡・トライアルの制度 | 特定団体の手続き |
| 迎える際の生活の変化 | 経済的な断定的助言 |
| 観察という方法そのもの | 訓練・しつけの技術 |

### 「しつけ」を扱わない理由

しつけは「猫を変える」行為であり、憲章§4.3（変わるのはプレイヤー）と対立する。
本作が扱うのは、猫を変える技術ではなく、**猫に合わせる方法**である。

※ トイレの場所を猫が選べるようにする、といった環境側の工夫は Pillar 3 の範囲であり、扱う。

## 6.7 転移の設計

学習が現実に転移するために、以下を満たす。

```
□ ゲーム内の因果関係が、現実の因果関係と一致している
□ 学んだことが、ゲーム内の別の個体でも通用する（周回での検証）
□ ゲーム内でしか通用しないルール（ゲーム的な嘘）が存在しない
□ 抽象度の高い理解（「観察する」「決めつけない」）が、明示的に言語化される
□ プレイヤー自身の言葉で表現された記録が、持ち帰れる
```

**最も転移してほしい学習は、猫の知識ではない。**

> **「わからない相手を、わかろうとする方法」**

これは猫以外にも適用できる。本作の教育的価値の最深部はここにある。

# ⑦ Observation Design

> **目的**: 「観察する楽しさ」を定義し、Pillar 1 を実装可能な設計原理に変換する。
> **背景**: 「観察が主行為」は宣言できても、それが楽しいかは別問題。観察の快感の構造を分解しなければ、実装で必ず「クリックして情報を見る」に退化する。
> **設計理由**: 観察の面白さは「情報の取得」ではなく「差分の発見」と「意味の推測」にある。この区別を設計原理として固定する。
> **期待する効果**: 観察関連のあらゆる仕様が、退化を検出できる基準を持つ。
> **他章への影響**: ⑥の第1層を供給。④M1・M2の実装基盤。⑬チェックリストG群の根拠。

## 7.1 観察の快感の分解

**観察はなぜ楽しいのか。** 四つの成分に分解する。

| # | 成分 | 快感の正体 | 設計要件 |
|---|---|---|---|
| **O-1** | **差分** | 「昨日と違う」を見つける | 基準となる日常が確立していること |
| **O-2** | **多層性** | 一つの現象に複数の読みがある | 曖昧さが意図的に残されていること |
| **O-3** | **不可視** | 見えないものを推し量る | 全部は見えないこと |
| **O-4** | **蓄積** | 過去の観察が今を照らす | 記録が参照可能で、意味を持つこと |

### O-1 差分 — 最も基礎的な快感

**差分が読めるためには、まず「いつも」が必要である。**

```
Day 1-5  で「いつも」を作る（同じ時間、同じ場所、同じ行動）
   ↓
Day 6-  「いつもと違う」が意味を持つ
```

これはPhase ②が退屈に見えても必要な理由でもある。
**基準の確立期間なしに、差分の快感は発生しない。**

設計要件：
- 猫の行動には**日常のパターン**が存在する
- パターンは数日で把握できる程度に単純
- 変化は**パターンからの逸脱**として現れる
- 逸脱は小さくてよい。むしろ小さいほうが発見の快感が大きい

### O-2 多層性 — 推理の余地

**同じ行動が、状況によって違う意味を持つ。**

```
「しっぽを振っている」
   ├─ 苛立っている？
   ├─ 何かに集中している？
   └─ 迷っている？
        ↑
    文脈がないと決まらない
```

設計要件：
- 一つのモーションに、**単一の意味を割り当てない**
- 意味は「モーション × 文脈（場所・時間・直前の出来事）」で決まる
- プレイヤーはモーションを覚えるのではなく、**組み合わせを読む**ようになる

これが「モーション図鑑を暗記すれば攻略できる」構造を防ぐ（原則3）。

### O-3 不可視 — 想像の余地

**見えないことが、観察を駆動する。**

見えないものの種類：
| 種類 | 例 | 役割 |
|---|---|---|
| 空間的に見えない | 家具の裏、別の部屋 | 探す動機 |
| 時間的に見えない | プレイヤー不在時、夜間 | 痕跡から推理する動機 |
| 本質的に見えない | 猫の内心 | 永久に推測であり続ける |

**「本質的に見えない」ものが存在し続けることが、本作の誠実さである。**
最後まで完全にはわからない。それでいい。

### O-4 蓄積 — 時間を味方につける

**過去の観察が、現在の観察の解像度を上げる。**

```
Day 3  の記録:「棚の上にいた」
Day 12 の記録:「音がした後、棚の上にいた」
Day 22 の観察:「棚の上にいる」→ 何かに驚いたのだと、根拠を持って推測できる
```

設計要件：
- 記録は残る。検索・参照できる
- ただし**記録を読む作業を強制しない**（作業化する）
- 記録は「思い出す助け」であって「攻略情報」ではない

## 7.2 「クリックして数値を見る」を防ぐ五原則

本作が最も陥りやすい失敗は、観察が「対象をクリックして情報ウィンドウを開く」行為に退化することである。

| # | 原則 | 内容 |
|---|---|---|
| **A** | 情報は「開く」のではなく「現れる」 | クリックで情報が出る構造を避ける。**時間経過と注視で現れる** |
| **B** | 情報は文章ではなく現象で | ウィンドウのテキストではなく、猫の動きそのものが情報である |
| **C** | 一度で全部わからない | 1回の観察で得られる情報を意図的に不完全にする |
| **D** | 見る場所を選ばせる | すべてを同時に見られない。**選択が発生する** |
| **E** | 数値・ゲージを一切使わない | 憲章 I-1 |

### 原則Dの重要性

「すべてを見られない」ことが、観察を**判断を伴う行為**にする。

```
今日、猫を見るか。トイレを確認するか。餌の減りを見るか。
   ↓
選択には理由がいる → 仮説が要る → 考える
```

ただしこれは「時間制限で焦らせる」設計とは異なる。
**選ぶことが負担ではなく、思考であるように設計する。**

## 7.3 観察の四次元

観察対象は以下の4軸で構成される。

```
        ┌─────────────────────────────────────┐
        │           観察の四次元               │
        ├──────────┬──────────────────────────┤
        │ 空間      │ どこにいるか / どこを避けるか │
        │           │ 部屋のどの領域を使うか      │
        ├──────────┼──────────────────────────┤
        │ 時間      │ いつ活動するか / いつ寝るか  │
        │           │ 何分続くか / どれくらいで終わるか │
        ├──────────┼──────────────────────────┤
        │ 頻度      │ 何度繰り返すか / 増えたか減ったか │
        ├──────────┼──────────────────────────┤
        │ 文脈      │ 直前に何があったか          │
        │           │ 誰がいるか / 何が変わったか  │
        └──────────┴──────────────────────────┘
```

**初心者は「空間」しか見ない。熟練すると「文脈」が見える。**
この移行そのものが、プレイヤーの成長（⑨）である。

## 7.4 観察対象のカテゴリ

| カテゴリ | 例 | 特性 |
|---|---|---|
| **猫本体** | 位置・姿勢・表情・耳・尻尾・目 | 直接的。ただし不在時は見られない |
| **痕跡** | 餌の減り・トイレ・抜け毛・爪跡・動いた物 | 不在時の情報源。Phase ② の主役 |
| **音** | 鳴き声・足音・喉の音・物音 | 画面外の情報。視覚的にも冗長提示（憲章 §9.8） |
| **環境の変化** | 使われた場所・避けられた場所 | Pillar 3 の検証手段 |
| **自分自身** | 自分の位置・動き・音 | 最も見落とされる。終盤で気づく |

### 「自分自身」を観察対象にする意味

Phase ⑤ での重要な気づきの一つは、
**「猫が反応していたのは、自分の振る舞いだった」**ということである。

これは Pillar 5（変わるのは猫ではない）の最も鋭い実装であり、
現実への転移価値が最も高い学習でもある。

## 7.5 観察の熟練度の表現

プレイヤーの観察が上達したことを、**数値ではなく表現の変化**で示す。

| プレイヤーの段階 | 同じ光景の描写 |
|---|---|
| 初期 | 「猫が、こちらを見ている」 |
| 中期 | 「猫が、耳を少し後ろに向けて、こちらを見ている」 |
| 後期 | 「猫が、耳を少し後ろに向けている。逃げる準備をしながら、こちらを確かめている」 |

**同じ現象。異なる解像度。**
描写の詳細度が、プレイヤー自身の理解の深さを映す鏡になる。

⚠️ 実装注意：この段階変化を「観察レベル」として数値化しない。
到達条件は内部で管理し、表に出さない。

# ⑧ Failure Philosophy

> **目的**: 本作における「失敗」を再定義し、罰のない学習環境を成立させる。
> **背景**: 憲章 I-4 によりゲームオーバー・勝敗は存在しない。しかし憲章§4.5は「失敗はなかったことにもならない」とする。この両立を体験レベルで設計する必要がある。
> **設計理由**: 失敗の扱いは学習設計の中核である。罰があれば挑戦しなくなり、結果がなければ学ばない。その中間を精密に設計する。
> **期待する効果**: 「うまくいかない体験」を、離脱ではなく学習に変換できる。
> **他章への影響**: ③Phase④の設計根拠。⑤N-04/N-09の回避策。⑨の成長は失敗を経由する。

## 8.1 失敗の再定義

**本作において「失敗」とは、猫にとっての悪い結果ではない。**

> ### 失敗とは、**仮説が外れること**である。

そして仮説が外れることは、**情報の獲得**である。
したがって本作に、純粋な意味での失敗は存在しない。

```
一般的なゲーム             本作
──────────────────         ──────────────────
失敗 = 進行の阻害          失敗 = 情報の獲得
失敗 = 罰                  失敗 = 除外できた選択肢
失敗 = やり直し            失敗 = 次の仮説の材料
```

## 8.2 三種類の「うまくいかなさ」

| 種類 | 内容 | プレイヤーの感情 | 扱い |
|---|---|---|---|
| **T-1 仮説の外れ** | 予測と違う結果 | 「そうか、違うのか」 | 歓迎する。情報として明示 |
| **T-2 過干渉による後退** | 焦った介入で関係が悪化 | 「やってしまった」 | **中核的学習**。責めずに見せる |
| **T-3 見送りという結末** | 迎えないという判断 | 「これでよかったのか」 | 失敗ではない。等価な結末 |

### T-1 仮説の外れ

**最も頻繁に起きる。そして最も価値がある。**

設計要件：
- 外れたことを明示しない（○×を出さない）
- 現象として結果を返す
- 外れた仮説も記録に残る（除外できた情報として）
- 外れたことへのネガティブな演出をしない

```
❌ 「予想は外れました」
❌ 落胆のSE、暗転
✅ 猫は、その場所を使わなかった。それだけを見せる
```

### T-2 過干渉による後退 — 本作の中核的失敗

**これは唯一、明確に「悪化」として設計される失敗である。**

なぜ必要か：
原則6「焦るほど悪循環になる」は、**体験されなければ理解されない**。
警告テキストでは伝わらない。実際に悪化させる必要がある。

設計要件：

```
□ 原因は必ず観測可能である（後から辿れる）
□ 悪化は段階的である（いきなり最悪にならない）
□ 悪化の持続時間は数日（即座に回復しない／永続もしない）
□ 回復経路が必ず存在する（詰みを作らない）
□ 回復の主な手段は「待つこと」である
□ プレイヤーを責めるテキストを出さない
```

**悪循環の構造**

```
焦り → 過干渉 → 猫の警戒上昇 → 猫が隠れる
                                    ↓
                        「もっと何かしなければ」← 焦りの増幅
                                    ↓
                              さらに過干渉
                                    ↓
                              さらに悪化
              ┌─────────────────────┘
              │
     ここで手を止められるか  ← 本作最大の学習ポイント
              │
              ↓
          待つ → 猫が落ち着く → 猫から動く
```

**この構造から抜ける唯一の方法が「何もしないこと」である。**
そしてそれを、ゲームは教えない。プレイヤーが気づく。

⚠️ 実装注意：
- 「何もしない」を選びやすくするUI上の配慮は必要（常時選択可能）
- ただし「何もしましょう」と促してはいけない
- 悪循環が長すぎると離脱する。**上限日数を設ける**（次工程で決定）

### T-3 見送りという結末

**憲章 I-9 により、これを失敗として演出することは禁止されている。**

設計要件：
```
□ 他の結末と同じ長さ・同じ演出品質で描く
□ 悲しい音楽を使わない（他の結末と同等のトーン）
□ 「残念でした」的な表現を一切使わない
□ 猫のその後を、不幸として描かない
□ プレイヤーの判断を、明示的に尊重する
□ ただし、過度に称賛もしない（それも評価になる）
```

現実的な背景の提示：
見送りは現実の譲渡において実際に起こることであり、
**猫にとって適切でない環境に無理に迎えることのほうが問題である**という事実を、
説教にならない形で提示する。

## 8.3 ゲームオーバーの不在

**本作にゲームオーバーは存在しない。**

| 一般的なゲームオーバー条件 | 本作での扱い |
|---|---|
| HP/体力の枯渇 | 存在しない |
| 時間切れ | 30日は終わるが、それは結末であって失敗ではない |
| 関係値の下限突破 | 存在しない（憲章 I-1） |
| 猫の死・逃亡 | **実装しない**（憲章 §9.4） |
| 詰み状態 | 設計上、発生させない |

### 「猫の死」を扱わない理由

- 脅威として使えば、プレイヤーは恐怖で動く。それは学習ではなく回避行動である
- 教育的価値がない。現実の飼育で「油断すると死ぬ」という理解は不正確かつ有害
- Mission 1（心理的ハードルを下げる）と真っ向から対立する
- 憲章 §9.4 で既に禁止

### 「逃亡」の扱い

脱走は現実に起こる重大なリスクであり、**知識としては扱う価値がある**。
ただし本編のゲームオーバー条件にはしない。

扱う場合の条件（次工程で判断）：
```
□ 発生しても取り返しがつく
□ 原因が明確に観測可能である
□ 恐怖ではなく注意として機能する
□ プレイヤーを責めない
```

## 8.4 「取り返しのつかなさ」と「詰みのなさ」の両立

Pillar 4（30日は戻らない）と、詰みの排除は、一見矛盾する。
両立の設計原理は以下である。

```
取り返しがつかないもの:  時間（その日はもう来ない）
取り返しがつくもの:      関係（時間をかければ回復する）
```

| 項目 | 可逆性 | 理由 |
|---|---|---|
| 経過した日数 | **不可逆** | Pillar 4 |
| 見なかった観察機会 | **不可逆** | 観察に価値を与えるため |
| 猫との関係の悪化 | **可逆**（時間がかかる） | 詰みを作らないため |
| 環境の変更 | 可逆 | 試行錯誤を促すため |
| 猫の健康・生命 | （悪化させない） | 憲章 §9.4 |

**失うのは機会であって、可能性ではない。**

## 8.5 失敗の演出における禁則

| 禁止する演出 | 理由 |
|---|---|
| ×マーク、失敗音 | Pillar 2 違反（正誤判定） |
| 画面の暗転・赤化 | 罰の記号 |
| 「失敗しました」のテキスト | 憲章 §10.2 語彙違反 |
| 猫の悲しそうな表情の強調 | 罪悪感による操作（I-10） |
| リトライの提案 | Pillar 4 違反 |
| 「もっと〜すべきでした」 | 説教（Mission 4 違反） |
| スコアの減少表示 | 憲章 I-1・I-4 |

### 代わりに使う表現

```
現象をそのまま見せる。
猫は、隠れた。
昨日まで使っていた場所を、今日は使わなかった。

——それだけ。
```

**評価を加えないことが、最も雄弁である。**

# ⑨ Player Growth

> **目的**: レベルアップに代わる成長の定義と、その体験・可視化の方法を確立する。
> **背景**: 憲章 I-3 により数値的成長は禁止。しかし成長実感がなければゲームは駆動しない。認知の変化を成長として設計する必要がある。
> **設計理由**: 成長を数値化しないという制約は、実は本作を強くする。数値で測れない成長のほうが、現実に転移する。
> **期待する効果**: 「進捗が見えない」という課題に対し、数値以外の解決手段を体系的に持てる。
> **他章への影響**: ⑥学習の成果物。④M4の実装。⑩へ接続する成長が転移対象。

## 9.1 何が成長するのか

**成長するのはプレイヤーである。**（Pillar 5）
そして成長する能力は3つに限定される。

```
┌────────────────────────────────────────────────┐
│  観察力  ── 何を見るべきかがわかる              │
│             見えるものの解像度が上がる           │
├────────────────────────────────────────────────┤
│  理解力  ── 見たものの意味が読める              │
│             文脈を考慮した解釈ができる           │
├────────────────────────────────────────────────┤
│  判断力  ── 何をすべきか / すべきでないかを決める │
│             「待つ」を選べるようになる           │
└────────────────────────────────────────────────┘
```

## 9.2 三つの成長軸の詳細

### 成長軸1: 観察力

| 段階 | 状態 | 行動の変化 |
|---|---|---|
| L1 | 猫しか見ない | 猫を探す |
| L2 | 痕跡に気づく | 餌・トイレを確認する |
| L3 | 時間の軸を持つ | 「いつも何時に」を意識する |
| L4 | 文脈を見る | 「直前に何があったか」を考える |
| L5 | 自分を見る | 自分の振る舞いを観察対象にする |

**L5への到達が、本作の観察力の到達点である。**

### 成長軸2: 理解力

| 段階 | 状態 | 思考の変化 |
|---|---|---|
| L1 | 意味がわからない | 「なんで？」 |
| L2 | 単純な法則を作る | 「◯◯だから」 |
| L3 | 例外に出会う | 「あれ、違う」 |
| L4 | 条件付きで理解する | 「◯◯のときは、◯◯」 |
| L5 | わからなさを受け入れる | 「たぶん。でも確かではない」 |

**L5が示すのは、断定しない成熟である。**
これは科学的態度そのものであり、本作の教育的価値の中核。

### 成長軸3: 判断力

| 段階 | 状態 | 行動の変化 |
|---|---|---|
| L1 | 何をすればいいかわからない | 手当たり次第 |
| L2 | 積極的に介入する | 毎日何かをする |
| L3 | 介入の失敗を経験する | 手を止める |
| L4 | 待つことを選べる | 「今日は見ているだけ」 |
| L5 | 自分の限界を認識する | 迎える／迎えないを、根拠を持って判断する |

**L5が Phase ⑥ の決断を支える。**

## 9.3 成長の可視化（数値を使わない方法）

| 手段 | 内容 | 効果 |
|---|---|---|
| **記録の文体変化** | 過去のノートが素朴に見える | 最も強い成長実感（M4） |
| **描写の解像度変化** | 同じ光景の説明が詳しくなる | 見る目の変化を実感 |
| **再解釈演出** | 序盤の場面が違って見える | Pillar 5 の直接体験 |
| **できることの増加** | 観察の選択肢が増える | ※ 能力解放にしないこと |
| **迷いの質の変化** | 序盤「何をすれば」→終盤「どちらが正しいか」 | 思考の深化 |

### 「できることの増加」の扱い（重要）

観察の選択肢が増えることは、**能力の解放ではなく、視野の拡大**として設計する。

```
❌ 「観察スキル Lv.2 を習得しました！」
❌ 「新しい観察方法がアンロックされました」
✅ 気づかないうちに、見る場所が増えている
✅ 「そういえば、餌の減り方も見られるな」とプレイヤーが思う
```

**解放の通知をしない。** 静かに増える。気づくのはプレイヤーである。

⚠️ ただしUX上、選択肢の存在が発見されない事態は避ける。
「通知しない」と「隠す」は違う。**常にそこにあり、見れば気づける**状態にする。

## 9.4 成長の証明 — プレイヤーが自覚する瞬間

成長は、以下の瞬間に自覚される。設計上、これらを必ず用意する。

| # | 瞬間 | 配置 |
|---|---|---|
| G-1 | 過去の自分の記録を読み返したとき | Phase ④以降、任意 |
| G-2 | 同じ光景が違って見えたとき | Phase ⑤（再解釈演出） |
| G-3 | 何もしないことを自分で選んだとき | Phase ④終盤 |
| G-4 | 猫の行動を予測して、当たったとき | Phase ⑤ |
| G-5 | 「わからない」と正直に言えたとき | Phase ⑤⑥ |
| G-6 | 決断の理由を、自分の言葉で持てたとき | Phase ⑥ |
| G-7 | 現実の猫を見て、見方が変わったと気づいたとき | Phase ⑦ |

**G-7 が本作の最終到達点である。** ゲームの外で起きる。

## 9.5 成長させないもの

| 項目 | 理由 |
|---|---|
| 猫の能力・性格 | 憲章 I-3・§4.3 |
| プレイヤーの操作技能 | アクション性は本作に不要 |
| 所持品・資産 | 収集動機の排除（I-7） |
| 猫との関係の数値 | 憲章 I-1 |
| 効率（時短） | 効率化は観察の敵 |

### 「効率」を成長にしない理由

多くのゲームで、熟練は「速くクリアできること」を意味する。
本作でそれが起きると、**観察をスキップする熟練者**が生まれる。これはPillar 1の破壊である。

したがって：
- 熟練しても、1日の所要時間は短くならない
- 熟練しても、猫が早く懐くようにはしない
- 熟練とは「同じ時間で、より多くを読み取れること」である

## 9.6 周回時の成長

2周目以降、プレイヤーは前回の知識を持っている。この扱いは慎重に設計する。

| 前回から持ち越すもの | 持ち越さないもの |
|---|---|
| 観察の方法（見方） | この個体の性格 |
| 一般的な猫の理解 | 有効だった具体的な打ち手 |
| 「待つ」という選択肢の存在 | 前回の正解 |

**周回は「効率的な1周目」であってはならない**（憲章 §14.3）。
前回の知識は**方法として**役立ち、**答えとしては役立たない**。

これが原則2（個体差）と原則3（正解は一つではない）の周回における実装である。

# ⑩ Reality Bridge

> **目的**: ゲーム体験を現実の意識・行動へ接続する導線を設計する。
> **背景**: 憲章§11.1により、本作の成功は「プレイヤーの価値観の変化」で測られる。これはゲーム外で確認される成果であり、接続点の設計が必須。
> **設計理由**: 社会的価値を持つゲームの大半は、接続点で失敗する。感動の直後に行動を促し、勧誘と受け取られて反発を招く。順序と温度の設計が成否を決める。
> **期待する効果**: Mission 1〜3 が、押し付けにならずに達成される。
> **他章への影響**: Pillar 7 の実装。Phase ⑦ の詳細。⑥の転移設計と接続。

## 10.1 設計の基本原則

> ### **ゲームの中で説得しない。ゲームの外に、扉だけを置く。**

| 原則 | 内容 |
|---|---|
| **R-1 分離** | ゲーム体験と現実情報を、明確に分ける |
| **R-2 事後** | 現実情報はプレイ中に出さない。終了後のみ |
| **R-3 余韻** | 感動の直後に置かない。間を挟む |
| **R-4 任意** | 無視して閉じられる。ペナルティなし |
| **R-5 中立** | 特定団体・業種を推奨も批判もしない（憲章 I-8） |
| **R-6 正確** | 提供する情報は事実に基づき、更新可能に保つ |
| **R-7 双方向** | 「迎える」だけでなく「迎えない」も尊重する |

## 10.2 四層の橋

現実への接続は、段階的に、温度を上げずに行う。

```
┌─────────────────────────────────────────────────────┐
│ 層1: 体験の中の現実性                                │
│      ゲーム内の知識・制度・描写が、すべて現実に基づく  │
│      → プレイヤーは気づかないうちに、現実を学んでいる  │
│      【プレイ中・全期間】                             │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│ 層2: 自己認識の言語化                                │
│      30日間の自分の記録が、読み返せる形で残る          │
│      「私はこう考えるようになった」が自分の言葉で残る   │
│      【エンディング直後 → 余韻の後】                  │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│ 層3: 情報への扉                                      │
│      現実の保護猫・譲渡・飼育に関する情報への静かなリンク│
│      押さなくてよい。存在するだけ                      │
│      【メニュー・エンディング後の任意項目】            │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│ 層4: 現実の行動                                      │
│      ゲームは関与しない。プレイヤーが自分で決める       │
│      【ゲームの外】                                   │
└─────────────────────────────────────────────────────┘
```

**層4に対して、ゲームは何もしない。** これが最も重要な設計判断である。

## 10.3 層1: 体験の中の現実性（最重要）

**最も効果が高く、最も押し付けにならない接続は、層1である。**

プレイヤーは「学ばされた」と感じないまま、正確な知識を得ている。
これが Mission 4（押し付けない）の最良の達成形である。

### 層1で担保すること

| 領域 | 現実性の担保 |
|---|---|
| 猫の行動 | 行動学的に実在する行動のみ |
| 環境の効果 | 実際の環境エンリッチメントの原理に基づく |
| トライアル制度 | 実在の制度に即した描写 |
| 譲渡の条件 | 過度に厳しくも甘くもない、現実的な範囲 |
| 費用・時間 | 実際の目安に基づく（断定は避ける） |
| 個体差 | 実際に猫に存在する多様性の範囲 |

**ゲーム独自の嘘を一切作らない。**
これは表現の自由度を下げるが、Mission の達成には不可欠である。

## 10.4 層2: 自己認識の言語化

エンディング後、プレイヤーは30日間の自分の記録を読み返せる。

### 提示するもの

```
□ 自分が立てた仮説の一覧（外れたものも含む）
□ 自分が気づいたことの記録
□ 自分が変えた環境の履歴
□ 「何もしなかった日」の記録
□ 最初の記録と最後の記録の対比
```

### 提示してはいけないもの

```
✗ スコア・評価・ランク
✗ 「観察回数: 47回」といった実績風の数値表示
   ※ 内部指標としては計測する（憲章§11.2）が、プレイヤーには見せない
✗ 「もっとこうすればよかった」という反省の押し付け
✗ 他プレイヤーとの比較
```

### 温度設計

層2は**振り返りであって、評価ではない**。
「あなたはこうでした」ではなく「あなたはこう書きました」を提示する。

解釈はプレイヤーに委ねる。

## 10.5 層3: 情報への扉

### 提供する情報の範囲

| 提供する | 提供しない |
|---|---|
| 保護猫の譲渡という仕組みの説明 | 特定団体への誘導 |
| 一般的な譲渡条件の目安 | 「あなたは条件を満たします」の判定 |
| 迎える前に考えるべきこと | 「迎えるべき」という推奨 |
| 迎えられない場合の関わり方 | 寄付・支援の要請 |
| 信頼できる情報源の探し方 | 特定サイトへの限定リンク |

### 「迎えられない人」への設計（R-7）

**本作のプレイヤーの多くは、実際には猫を迎えない。**
その人たちを、達成できなかった人として扱わない。

提示する選択肢の幅：
```
・迎える
・今は迎えないが、いつか考える
・迎えないが、理解者として存在する
・別の形で関わる（保護活動の周辺、預かり、情報の共有など）
・何もしない
```

**「何もしない」も、選択肢として明示的に肯定する。**
これが Mission 3（偏見をなくす）の裏側にある、プレイヤーへの偏見の排除である。

### 配置と意匠

```
□ ゲーム内UIと明確に異なる意匠にする（ここからは現実だとわかる）
□ ボタンではなく、テキストリンクに近い静かな提示
□ エンディング直後ではなく、余韻を挟んだ後
□ メニューからいつでもアクセスできる（強制しない）
□ 開かずに閉じられる
```

## 10.6 やってはいけない導線

| 禁止事項 | 理由 |
|---|---|
| エンディング直後の寄付ボタン | 感情操作。憲章 I-10 の精神に反する |
| 「保護猫を迎えよう」の直接的呼びかけ | Mission 4 違反（押し付け） |
| SNS拡散の強い促し | 体験の私的性を損なう |
| メールアドレス登録の要求 | 信頼の毀損 |
| 「◯人がこのゲームの後に猫を迎えました」 | 社会的圧力による誘導 |
| ペットショップ批判 | 憲章 I-8 |
| 感動的な実話の直後の行動喚起 | 感情操作 |
| 「あなたは良い飼い主になれます」 | 根拠のない保証。無責任 |

## 10.7 効果測定

Reality Bridge の効果は、ゲーム内指標では測れない。

| 測定対象 | 方法 | 注意 |
|---|---|---|
| 意識の変化 | プレイ後アンケート（任意） | 回答を強制しない |
| 情報層への到達率 | アクセス解析 | 高ければ良いとは限らない |
| 現実の行動 | 測定しない | 追跡はプライバシー侵害 |

**「何人が猫を迎えたか」を成功指標にしない。**
それを指標にした瞬間、設計が誘導的になる。

本作の成功指標は、あくまで**プレイヤーの内側の変化**である（憲章§11.2）。

# ⑪ Emotional Rewards

> **目的**: アイテム・経験値・レベルに代わる報酬体系を、感情のレベルで設計する。
> **背景**: 憲章 I-3・I-5・I-7 により物質的報酬が全面的に使用不可。報酬の空白は必ず「何か足そう」という圧力を生むため、代替を明示する。
> **設計理由**: 報酬とは本来、脳内の状態変化である。物質的報酬はその代理にすぎない。代理を外して直接設計することは可能であり、本作ではむしろ適している。
> **期待する効果**: 「報酬がない」ではなく「別種の報酬がある」として設計・議論できる。
> **他章への影響**: ④の動機を支える。③の各Phaseに配分される。⑫の禁止報酬リストと対をなす。

## 11.1 報酬の四分類

```
┌──────────────────────────────────────────────────┐
│ ER-A  解読報酬  ── 「わかった」                    │
│        認知的閉合の快感。本作の主報酬              │
├──────────────────────────────────────────────────┤
│ ER-B  関係報酬  ── 「近づいてきた」                │
│        相互性の知覚。強力だが取扱注意              │
├──────────────────────────────────────────────────┤
│ ER-C  自己変化報酬 ── 「変わった」                 │
│        有能感。最も持続する                        │
├──────────────────────────────────────────────────┤
│ ER-D  美的報酬  ── 「きれいだ」「心地よい」        │
│        感覚的快。全期間の基層                      │
└──────────────────────────────────────────────────┘
```

## 11.2 各報酬の設計

### ER-A 解読報酬（主報酬）

| 項目 | 内容 |
|---|---|
| **正体** | 断片が繋がり、意味をなす瞬間の快感 |
| **強度の決定要因** | 繋がるまでの距離（時間・情報の隔たり） |
| **発生タイミング** | Phase ③（小）／Phase ⑤（大） |
| **演出方針** | **祝わない**。静かに、しかし確実に |

**演出設計（重要）**

```
❌ 効果音 + カットイン + 「わかった！」のテキスト
✅ 描写が変わる。それだけ。
   「猫が、こちらを見ている」
    → 「猫が、こちらを見ている。逃げる準備をしながら」
```

**祝わない理由**: 祝った瞬間、それは外的報酬になる。
解読報酬は内発的であり、外から祝われると価値が下がる（アンダーマイニング効果）。

### ER-B 関係報酬

| 項目 | 内容 |
|---|---|
| **正体** | 相手が自分に反応しているという知覚 |
| **強度** | 最強。ただし最も危険 |
| **発生タイミング** | Phase ③（初の接近）／Phase ⑤（自発的接近） |
| **演出方針** | 小さく、確実に。理由が理解可能な形で |

**取扱注意事項**

```
□ 目標として提示しない（SF-3 参照）
□ 進捗として可視化しない
□ 演出で祝わない
□ 「なぜそうなったか」を必ず理解可能にする
□ 一方向にしない（近づいたり離れたりする）
```

**最重要ルール**:
> 関係報酬は、**それ単独では与えない**。
> 必ず ER-A（なぜそうなったかの理解）とセットで与える。

これが「懐かせるゲーム」への転落を防ぐ唯一の安全弁である。

### ER-C 自己変化報酬

| 項目 | 内容 |
|---|---|
| **正体** | 自分が上達している、変わっているという実感 |
| **強度** | 中〜強。持続性は最高 |
| **発生タイミング** | Phase ⑤⑥⑦ |
| **演出方針** | 過去との対比。プレイヤー自身に発見させる |

**実装手段**
- 過去の記録の参照（M4）
- 再解釈演出（Pillar 5）
- 描写の解像度変化（⑦7.5）

**注意**: 「成長しました」と言わない。
プレイヤーが自分で「成長した」と思うことが報酬である。

### ER-D 美的報酬

| 項目 | 内容 |
|---|---|
| **正体** | 見ていて心地よい、音が気持ちいい、空間が美しい |
| **強度** | 弱いが常時作用 |
| **発生タイミング** | 全期間 |
| **演出方針** | 生活の質感。過度な美化をしない |

**本作における美とは**
- 日常の光。窓から差す午後の陽
- 生活音。冷蔵庫、遠くの車、雨
- 猫の身体の自然な動き
- 整えられた部屋の落ち着き

**避けるもの**
- ファンタジックな演出、パーティクル
- 過度に彩度の高い色
- 「映える」ためだけのカット

美的報酬は Pillar 6（静けさ）と一体である。
**静けさが心地よいと感じられることが、本作の美的成功である。**

## 11.3 報酬タイミング設計

```
報酬強度
   │                                    ER-A（大）
   │                                    ER-B（大）
   │                                    ER-C
   │                              ╱╲   ╱
   │                   ER-A(小)  ╱  ╲ ╱
   │        ER-B(初)  ╱╲       ╱
   │   ╱╲            ╱  ╲     ╱
   │  ╱  ╲──ER-D──╱────╲───╱─────────  基層
   └──────────────────────────────────────→
    ①    ②      ③      ④      ⑤    ⑥  ⑦
```

| Phase | 主報酬 | 内容 |
|---|---|---|
| ① | ER-D | 空間の心地よさ |
| ② | ER-D + 微少なER-B | 最初の目撃 |
| ③ | ER-A（小）+ ER-B | 仮説的中、初の接近 |
| ④ | **報酬を絞る** | 停滞期。ER-Dのみ維持 |
| ⑤ | **ER-A（大）+ ER-B + ER-C** | 最大ピーク |
| ⑥ | ER-C | 決断の重みと自覚 |
| ⑦ | ER-C | 変化の自覚 |

**Phase ④ で報酬を絞ることが、Phase ⑤ の強度を決める。**
ここで報酬を足す誘惑に負けると、作品全体の感情設計が崩れる。

## 11.4 報酬にしてはいけないもの

| 禁止報酬 | 理由 |
|---|---|
| アイテム | 憲章 I-7・収集動機 |
| 経験値・レベル | 憲章 I-3 |
| 実績・トロフィー | 憲章 I-7 |
| 新しい猫の解放 | 猫が報酬になる（憲章の根幹に反する） |
| 装飾品・スキン | 収益化への接続。猫の外見の消費 |
| ストーリーの解放 | 学習を報酬で釣る構造（I-7） |
| 猫の「特別な仕草」の解放 | 猫の性能化（I-3） |
| ランキング上位 | 憲章 I-4 |
| 称号 | プレイヤーの評価。I-4 の精神に反する |

## 11.5 報酬設計の判定基準

新しい報酬要素を検討する際：

```
□ その報酬は、プレイヤーの内側で発生するか（外から与えられていないか）
□ その報酬は、猫を手段にしていないか
□ その報酬は、収集・蓄積を促していないか
□ その報酬がなくても、その行動をしたくなるか
    → NO なら、その行動設計自体が間違っている
□ その報酬は、理解とセットになっているか
□ その報酬は、祝われずに済むか
```

**最後の項目が本質的である。**
祝わなければ成立しない報酬は、本作には不要な報酬である。

# ⑫ Anti Patterns

> **目的**: 導入してはならない要素を網羅的に列挙し、判断コストをゼロにする。
> **背景**: 長期開発では、善意の提案が徐々に作品を侵食する。「これは良くないか？」の判断を毎回行うことがコストであり、判断のブレを生む。
> **設計理由**: 事前に列挙しておけば、議論は「リストにあるか」で終わる。リストにない場合のみ、原則に立ち返って議論する。
> **期待する効果**: レビュー時間の短縮と、判断の一貫性の担保。
> **他章への影響**: ⑬チェックリストの根拠。憲章 付録B の拡張版。

## 凡例

| 記号 | 意味 |
|---|---|
| 🔴 | 絶対禁止（憲章の不可侵条項に抵触） |
| 🟠 | 原則禁止（Pillar・原則に反する） |
| 🟡 | 条件付き禁止（実装次第で可。要individual判断） |

# ⑬ Quality Checklist

> **目的**: あらゆる成果物（システム・イベント・UI・演出・ストーリー）を、統一基準で評価可能にする。
> **背景**: 憲章§13の機能適合チェックリストは「採用/却下」のゲート。本章は「品質」の検証であり、採用後の実装物を対象とする。
> **設計理由**: 判断を属人化させないためには、YES/NOで答えられる形式が必要。曖昧な基準はレビューを主観論争にする。
> **期待する効果**: レビューの再現性・客観性の確保。新規参加者でも品質判断ができる。
> **他章への影響**: 全章の検証装置。①〜⑫のすべてがここで検査される。

## 13.3 プレイテスト用検証質問

チェックリストが「作り手の検証」であるのに対し、以下は「プレイヤーでの検証」。

### 体験の成立確認

```
□ V-01 今、画面に何が見えますか？（答えられない → 退屈。N-14）
□ V-02 明日、何が知りたいですか？（答えられない → M1 の不成立）
□ V-03 この猫は、どんな子だと思いますか？（一般論しか出ない → 個体理解の不成立）
□ V-04 うまくいかなかったとき、原因は何だと思いましたか？
       （「わからない」→ N-04 理不尽）
□ V-05 このゲームを一言で説明してください
       （「懐かせるゲーム」→ Pillar 5 の伝達失敗）
```

### 学習の成立確認

```
□ V-06 何か学びましたか？（「猫は〜だ」と一般論 → 第3層のみ。第2層の不成立）
□ V-07 それは、どうしてわかりましたか？（説明できない → 理解ではなく知識）
□ V-08 現実の猫にも当てはまると思いますか？（転移の確認）
```

### 価値観変化の確認

```
□ V-09 保護猫を迎えることについて、印象は変わりましたか？
□ V-10 猫の見方は変わりましたか？
□ V-11 誰かに何か伝えたくなりましたか？
```
