## 0. この文書の役割

保護猫トライアル30日は、**猫を操作するゲームではなく、猫を理解するゲーム**（`docs/00:101` / `docs/18`）。
したがってアートの仕事は「かわいく飾ること」ではなく、**プレイヤーが推論できる材料を、正確に、やさしく見せること**。

本書は次の6段で構成する（制作の実行順もこの順）:

| § | 内容 | 成果物 |
|---|---|---|
| 1 | 世界観の確定 | 方向性・NG・立ち位置 |
| 2 | デザインガイド | 色・書体・線・形・余白・UIルール |
| 3 | 猫の描き方 | 絵柄の中核原則 |
| 4 | 猫の生成体系 | パーツ分解・seed 生成・ポーズ表 |
| 5 | 画面設計 | 画面インベントリとレイアウト |
| 6 | 素材パーツ表 | 生成プロンプト付きアセット一覧 |
| 7 | 組み立て | レイヤ構成と実装の受け皿 |

**アセット制作方式は「ハイブリッド」で確定**（2026-07-29 決定・§7.1）:

```
背景・部屋      ── 画像生成AI（ラスター・非透過）
家具・小物・痕跡 ── 画像生成AI（ラスター・透過PNG/WebP）
UIアイコン      ── 手描きSVG（または生成 → SVG トレース）
猫             ── SVGパーツ合成（コード生成・seed から決定論的に個体を描き分ける）
```

理由は §4.2 に述べる。要点は「**猫だけは毎回違う個体でなければならない**（`docs/18` B-A が全ブロックの前提）ので、猫を固定画像にすると、コアループの土台が絵の側から崩れる」。

## 1. 世界観（Step 1）

### 1.1 一行で

> **午後の陽が差す、木の匂いのする部屋。そこに、まだあなたを知らない猫が一匹いる。**

この一行に、本作の絵のすべてがある。**部屋は温かい。猫はまだ温かくない。** その距離が絵の主題。

### 1.2 誰に向けて

| 項目 | 内容 |
|---|---|
| 年齢 | 20〜40代 |
| 属性 | 猫好き。保護猫に関心はあるが、実際の預かり経験はない初心者 |
| 心理 | 「飼ってみたいけれど、自分に務まるか分からない」 |
| 絵に期待するもの | 責められない安心感。押しつけがましくない情報。**現実の保護猫を、美化も悲惨化もせずに見せてくれること** |

⚠️ **感傷の演出を絵で行わない。** 涙・雨・鎖・檻・痩せた体・悲しげな目——保護猫を題材にした表現が陥りがちな記号は、すべて使わない。本作の立場は憲章 I-9（見送りを失敗として演出しない・`docs/00:77`）であり、**同情ではなく理解**を求める。

### 1.3 立ち位置（リアル ↔ 記号）

ユーザー要件は「リアルすぎない／アニメ調すぎない」。これは中間ではなく、**軸ごとに振り分ける**ことで解決する。

| 軸 | 寄せる方向 | 理由 |
|---|---|---|
| **プロポーション** | デフォルメ寄り（2.5頭身・§3.1） | 親しみやすさ。初心者の心理的ハードルを下げる |
| **姿勢・体の動き** | **写実寄り**（実際の猫の姿勢を守る） | ここが推論の材料。嘘をつくとゲームが壊れる |
| **顔・表情** | **記号を抑える**（§3.3） | 表情で心情を語ると観測境界 I-1 が絵の側から破れる |
| **質感（毛・木・布）** | 中間（面で描き、テクスチャは最小） | 写実的な毛並みは重く、フラットすぎると温度が消える |
| **色** | やわらかい低彩度 + 差し色1つ | `docs/17` の確定トークンを継承 |
| **線** | あり（均一な太線・§2.5） | 絵本的な安心感。線があると「作り物」として安全に見られる |

一言でいえば **「観察に耐える体、責めてこない顔」**。

### 1.4 視覚の三原則

1. **同じ窓から、同じ部屋を見る**（`docs/17` §1-3 / B3 ③）
   構図は固定。カメラは動かない。ズームしない。変わるのは**猫と、光と、痕跡**だけ。
   → 制作上の恩恵が大きい: **背景は昼夜2枚で足りる**。予算はすべて猫のポーズと痕跡に注げる。

2. **影に黒を使わない**
   影はすべて暖色の乗算（`rgba(122,96,70,.16)`）。黒い影を1つ入れた瞬間に、部屋は冷たくなる。

3. **絵は騒がない**（Pillar 6）
   キラキラ・光の粒子・ハートマーク・達成の演出は持たない。動きは呼吸と尻尾だけ。

### 1.5 Do / Don't

| ✅ Do | ❌ Don't |
|---|---|
| 木の家具（明るい針葉樹・無塗装〜クリア） | 濃い茶のアンティーク家具（重く、古びて見える） |
| 左手の窓から差す自然光 | 天井照明のフラットな明かり（昼の画で使わない） |
| 生成りの布・綿・麻 | 光沢のある素材・ビニール・金属 |
| 猫が部屋の中にいる画 | 猫の「立ち絵」を白背景で切り出す（§5.1） |
| 空っぽの部屋（不在の時間） | 空白を埋めるための装飾追加 |
| 手描きの、わずかに歪んだ線 | 定規で引いた完全な直線・完全な円 |
| さくら耳・地域猫のリアリティ | 首輪のリボン・洋服・擬人化 |
| 落ち着いた低彩度 | ビビッド・ネオン・虹色・グラデ多用 |
| 余白 | 情報の詰め込み |

### 2.2 ⚠️ 「木目調UI」は採らない — 木はどこに置くか

要望に「ボタンは木目」「木目調UI」があったが、**UI パーツに木目テクスチャは載せない**。理由:

1. **`docs/17` の確定と衝突する**。ボタンは honey 単色の丸薬型で人間承認済み（`docs/17` §3）。
2. **honey が主役色として機能しなくなる**。「唯一の主役色＝今できる操作」（`docs/17` §3）という設計は、周囲が無地だから成立する。木目ボタンは操作の所在をぼかす。
3. **ダークで破綻する**。木目テクスチャは暗所で濁り、コントラスト比の確保が難しい。
4. **A11y**。テクスチャ上の文字は可読性が落ちる。

**代わりの解**——木の温かみは**絵の中**が担当する:

| 層 | 木の扱い |
|---|---|
| シーン（部屋の絵） | **ここが木の主戦場**。床・棚・テーブル・キャットタワー。§2.1.2 の階調をフルに使う |
| カード・ボタン（UI） | 木目なし。無地。ただし**カード縁に紙のような微細なざらつき**（`opacity .03` 以下）は可 |
| 見出し・区切り | 木目ではなく、`hair` の細い罫 |

> UIは「器」、絵は「中身」。器に木目を彫ると、中身が見えなくなる。

### 2.3 書体

`docs/17` §3 を継承（変更なし）。

- **丸ゴシック**: `"Hiragino Maru Gothic ProN"` → `"Rounded Mplus 1c"` → `"Hiragino Sans"` / `"Yu Gothic UI"` → `system-ui`
- **日本語 Web フォントは埋め込まない**（CSP・容量）。丸みは**形（角丸・丸薬ボタン）で担保**する。

| 用途 | サイズ | ウェイト | 行間 |
|---|---|---|---|
| タイトル | 1.8rem | 800 | 1.4 |
| **観察文（主役）** | **1.3rem** | **700** | 1.75 |
| 結末の語り | 1.4rem | 700 | 2.0 |
| ボタン | 0.85rem | 700 | — |
| 進行（N日目） | 0.8rem | 600 | — |
| ノート本文 | 0.9rem | 600 | 1.75 |
| 補助（復元通知） | 0.72rem | 600 | — |

⚠️ **観察文がページ内で最大の文字**（結末を除く）。これは「言葉が主役」という設計の直接表現。絵はその隣にいる。

### 2.4 線

| 対象 | 太さ（viewBox 100 基準） | 色 |
|---|---|---|
| **猫の外形** | **2.8** | `#4a3b30`（sumi-brown） |
| 猫の内部線（耳の内側・脚の分割） | 2.0 | `#4a3b30` |
| 家具・背景 | 2.0 | `#6b5949`（猫より淡く＝猫が前に出る） |
| UIアイコン | 2.4（24px グリッド） | `currentColor` |
| 痕跡オブジェクト | 2.0 | `#6b5949` |

**共通ルール:**
- `stroke-linecap: round` / `stroke-linejoin: round` **固定**。角のある線端は使わない。
- **線に黒（`#000`）を使わない。** 最も濃い線でも `#4a3b30`。
- 毛柄の境界は**線を持たない**（面の切り替えのみ）。線を入れると縫いぐるみのパッチワークに見える。
- 手描き感は**わずかな線幅の揺らぎ**（±0.2）で出す。完全に均一だとベクター臭くなる。

### 2.5 かたち・余白・グリッド

| 対象 | 角丸 |
|---|---|
| カード | 24px |
| シーン窓 | 20px |
| ノート／仮説帳 | 16px |
| **ボタン** | **999px（丸薬型）** |
| 小物・チップ | 8px |

**余白は 4px グリッド。基準単位は 16px**（要望どおり）:

```
4  ── 文字と付随アイコンの間
8  ── 密接する要素
12 ── ボタン間（0.6rem ≒ 9.6px を 12 に丸める）
16 ── 基準。カード内側の左右／ブロック間
24 ── カード内側の上下／セクション間
32 ── 大きな区切り（観察文と操作群の間）
```

**レイアウト**: 中央固定・カード幅 `26rem`（416px）・スマホ 375px では左右 16px。
`docs/17` の「構図は中央固定」を維持。**横幅いっぱいに広げない**——余白が静けさを作る。

### 2.6 ボタン

3種のみ。増やさない。

| 種類 | 見た目 | 意味 |
|---|---|---|
| **Primary** | honey 背景・白文字・丸薬 | **今できる操作**（ご飯をあげる／決める／つづける） |
| **Secondary** | surface-2 背景・ink-2 文字・丸薬 | 副次（次へ／見守る） |
| **Disabled** | 同上・`opacity .4` | できないこと。**理由は言わない、ただ静かに沈む** |

- 押下: `transform: scale(.97)` + 120ms。**リップル・バウンス・効果音は持たない**（Pillar 6）。
- ホバー: 明度 +4% のみ。
- ⚠️ **ボタンは操作群ごとに最大3つ、群は2つまで**。介入は有限（B2 §4）であり、選択肢の多さは「操作ゲーム」の合図になる。
  - 現状: 〈今できること〉ご飯をあげる／見守る／次へ ＋〈部屋を整える〉隠れ家／高い台／ごはんの位置。
  - **一度きりの設置は済むと沈む**（無効化）ので、実際に押せるボタンは時間とともに減っていく。
  - ⚠️ 初版は「画面あたり最大3つ」としていたが、EP-4.04 の環境アクションが**別の見出しを持つ群**として入ったため、
    群単位の規則に改めた。意図（選択肢の多さで「操作ゲーム」に見せない）は変えていない。

### 2.7 アイコン

- **24px グリッド・線画・線幅 2.4・`currentColor`・角丸端**
- **塗りつぶしアイコンを使わない**（線画で統一）
- 最小限。ラベルの代わりではなく、**ラベルの隣の小さな挿し絵**

| アイコン | 用途 |
|---|---|
| 🐾 肉球 | 観察ノート／仮説帳の見出し |
| 食器 | ご飯をあげる |
| 目 | 見守る |
| 段ボール | 隠れ家を置く（`docs/18` B-D） |
| 棚 | 高い場所を作る（同上） |
| 人の足あと | 距離をとる／近づく（同上） |
| 月・太陽 | 時間帯（`docs/18` B-B） |

⚠️ **ハート・星・王冠・トロフィー・鍵・炎は禁止**。すべて達成/収集の記号であり、Pillar 6 に反する。

### 2.8 UIルール（憲章の絵版・**不変**）

これはデザインの好みではなく、**破ると企画が壊れる規則**。

| U-2 | **猫の内面を絵で語らない**。表情記号（汗・怒りマーク・ハート目）を持たない | B4 P-01 |

### 2.9 ダーク（夜の部屋）

`theme.ts` のダークトークンは実装済み（EP-3.12）。**絵の側の夜の作り方**を以下に定める。

| 要素 | 昼 | 夜 |
|---|---|---|
| 光源 | 左の窓から自然光 | **室内の低い灯り**（`night-lamp`）。光源は画面下寄り |
| 窓 | 明るい `light-core` | `night-window`（**唯一の寒色**） |
| 影 | 短く・淡く（`shade`） | 長く・やわらかく。ただし濃度は上げない |
| 木 | `wood-pale` が主 | `wood-mid` が主。`wood-pale` は灯りの当たる縁のみ |
| 猫 | 毛色そのまま | **毛色の明度を下げない。灯りの当たる面に `night-lamp` を薄く乗せる** |

⚠️ **単純な暗色フィルタ／明度反転は禁止**。木目が濁り、部屋が冷たくなる（`theme.ts:8` の既存方針と一致）。

## 3. 猫の描き方（アートの中核）

### 3.1 ⚠️ プロポーションは 2頭身ではなく **2.5頭身**

要望は「2頭身」だったが、本作では**2.5頭身**を採る。理由:

> 2頭身は**顔で語るキャラクター**のための比率。本作は**体で語る**（§3.3）。
> 2頭身では胴が潰れ、「丸くなって休む」「耳を動かしじっとしている」「毛づくろい」の**姿勢の差が読めなくなる**。
> 姿勢の可読性は、このゲームでは装飾ではなく**推論の材料**そのもの（`docs/18` B-B）。

| 部位 | 比率（座り姿・全高100） |
|---|---|
| 頭（耳を除く） | 38 |
| 胴 | 46 |
| 前脚の見える部分 | 16 |
| 耳の高さ | +14（頭の上） |
| 尻尾の長さ | 胴の 1.3 倍 |

- **輪郭に鋭角を作らない**。頬・肩・尻はすべて円弧。
- **接地を必ず描く**（`shade-soft` の楕円）。浮いた猫は不安を呼ぶ。
- シルエットだけで姿勢が判別できること——**制作時の検品方法: 猫を単色に塗りつぶして、6つのポーズが区別できるか確認する**。

### 3.2 顔

| 部位 | 描き方 |
|---|---|
| 目 | **円 + 小さなハイライト1点**。瞳孔の縦長スリットは入れない（緊張して見える） |
| 目の大きさ | 頭幅の 1/6。**アニメ的な巨大な目にしない**（1.3 の要件） |
| 鼻 | 小さな三角（`#c98d86`）。幅は頭幅の 1/12 |
| 口 | **原則描かない**。「毛づくろい」時のみ ω 形を許可 |
| ひげ | 片側3本・線幅 1.4・両端フェード |
| 頬（blush） | `#f0b39c` を極小・`opacity .35`。**常時ではなく、休息ポーズのみ** |

### 3.3 ⚠️ **顔で語らない。体で語る。**

これが本作の絵の**最重要原則**であり、他のすべてに優先する。

観察文が「見えた事実だけを言う」（`phenomena.ts:5`「猫の内面の解釈を書かない」）のと**まったく同じ規律を、絵にも課す**。
絵が「怖がっている顔」を描いてしまえば、テキストがどれだけ禁欲的でも観測境界（憲章 I-1）は破れる。

| 語ってよいもの（観測可能） | 語ってはいけないもの（内面の解釈） |
|---|---|
| 耳の向き | 眉の角度 |
| 体の向き・プレイヤーへの角度 | 目を細める/見開く（感情表現として） |
| 部屋の中の**位置**（人との距離・高さ・遮蔽） | 涙・汗・赤面 |
| 姿勢の高さ（伏せ／座り／立ち） | 感情記号（♪ ♥ 💢 …） |
| 尻尾の位置 | 「安心した表情」 |
| 体の緊張（丸まり具合） | 吹き出し・思考の可視化 |

> **心情は、プレイヤーが猫の位置と姿勢から推し量るもの。絵は答えを言わない。**
> これは `docs/06`（Player Knowledge）の「観測していないものは材料にならない」（`docs/06:660`）の視覚版。

### 3.4 さくら耳

保護猫（TNR 済み地域猫）のリアリティとして**片耳の先端 V 字カット**を採用する。

- **個体により有無**（§4.2 の生成テーブルで確率的に決まる）。全個体に付けない——全個体に付けると記号化する。
- 左右どちらかはランダム。日本では左耳が主流（雄）／右耳（雌）の慣習があるが、**地域差があるため厳密な規則にはしない**。
- ⚠️ **傷・欠け・血は描かない**。V字は治癒済みの、きれいなカット。

### 3.5 ⚠️ **見た目と気質を相関させない**

`docs/18` B-A で CatProfile（神経質さ・遮蔽選好・高所選好・社会性）が導入される。
**このパラメータと、毛柄・体格・顔つきを相関させてはならない。**

理由は2つある:

1. **ゲームが壊れる**。「黒猫は臆病」のような対応があると、プレイヤーは**観察せずに見た目で当てられる**。観察→仮説→働きかけ→答え合わせのループ（`docs/18` §1）が、開始1秒でショートカットされる。
2. **現実に対して不誠実**。毛柄と性格を結びつける俗説の再生産は、保護猫を題材にする作品として採れない。実際の譲渡現場でも「見た目で決めない」ことは繰り返し伝えられている。

```
CatProfile（気質）  ──┐
                      ├─ 独立した RNG stream から生成する
Appearance（見た目）──┘   （相関ゼロ。交差させない）
```

**唯一の手がかりは、観測可能な振る舞い**——姿勢・位置・耳の向き・距離・時間帯。それだけ。

> 補足: `docs/06:1176`（誤解設計）の観点では「見た目で誤解させる」設計もあり得る。しかし**その誤解は正誤が示されない**（U-8）ため、プレイヤーの中に俗説が確定して残る危険がある。本書は採らない。

## 4. 猫の生成体系（Step 5）

### 4.1 パーツ分解

猫は**1枚絵ではなく、7つの独立レイヤの合成**として定義する。

| # | レイヤ | バリエーション | 備考 |
|---|---|---|---|
| L1 | 体型シルエット | 3（細身 / 標準 / むっちり） | ポーズごとに用意 |
| L2 | 毛の地色 | 6（§4.2 表） | |
| L3 | 模様 | 5（無地 / 縞 / ハチワレ / ぶち / 三毛） | 地色と組で有効な範囲を制限 |
| L4 | 白の入り方 | 4（なし / 靴下 / 胸 / 顔から胸） | |
| L5 | 耳 | 2（通常 / さくら耳）× 左右 | |
| L6 | 目の色 | 3（琥珀 / 黄緑 / 銅） | 低彩度で |
| L7 | 尻尾 | 3（長 / 中 / かぎ尻尾） | かぎ尻尾は日本猫のリアリティ |

**組み合わせ数**: 実効で 400 通り以上。全個体を画像で持つのは不可能——だから猫は SVG コード合成（§7.1）。

### 4.2 毛色テーブル

| id | 和名 | 地色 | 差し色 | 白 |
|---|---|---|---|---|

| `coat.tabby` | キジトラ | `#c0a480` | `#96794f` | — |

### 4.3 seed からの生成

**EP-4.01 で実装済みの `generateCatProfile`（[catProfile.ts](src/simulation/catProfile.ts)）と対称の形で書く。**

```
rootRng.fork('appearance')   ← 'profile' とは別ストリーム（§3.5・交差させない）
   ↓
L1..L7 を順に決定（重み付き抽選）
   ↓
Appearance { body, coat, pattern, white, ears, eyes, tail }
   ↓
保存不要（f(seed) で再生成可能・CatProfile と同じ扱い）
```

⚠️ **層が CatProfile と異なる。** CatProfile は L2 限定で L4 に出してはならない（[catProfile.ts:6](src/core/state/catProfile.ts#L6)）が、
**Appearance は L4 が描画に使う**ため L4 に渡ってよい。ただし渡すのは**描画パラメータのみ**で、気質は一切含めない（§3.5）。
生成は合成ルート（`src/app`）が行い、L4 へ渡す。

- **完全ランダムにしない**（`docs/04:1910` の方針を踏襲）。実在する日本猫の分布に寄せた重み付け（キジ白・黒白が多め、三毛は雌のみ）。
- さくら耳の出現率は**約 40%**（全個体に付けない・§3.4）。

### 4.4 ポーズ表（現象語彙と1対1で対応）

**絵は現象語彙（descriptor）の従属物**。語彙にないポーズを作らない、語彙にあるポーズは必ず作る。

#### 実装済み語彙（[phenomena.ts](src/content/phenomena.ts)）

| descriptor | 表示文 | ポーズ | 絵のポイント | 現行 sprite |
|---|---|---|---|---|
| `curled_resting` | 丸くなって休んでいる | アンモナイト | 鼻を尻尾に埋める。**耳は寝かせない**（安心と読ませない） | `cat_curled` ✅ |
| `ears_orienting` | 耳を動かし、じっとしている | 座位・耳だけ他方向 | **体と視線は動かさない、耳だけ**。緊張の記号を足さない | `cat_alert` ✅ |
| `roaming` | 部屋を歩き回っている | 横向き歩行 | 尾は水平。4脚が見える | `cat_walking` ✅ |
| `at_food` | 食器のところにいる | 前傾・頭が下がる | 食べているとは限らない。**食器の前にいるだけ** | `cat_eating` ✅ |
| `self_grooming` | 毛づくろいをしている | 後脚を上げる／前脚を舐める | 体を折る。後脚が縦に伸びるシルエットが決め手 | `cat_grooming` ✅ |

| `at_refuge` / `at_vantage` / `at_open_floor`<br>（subject: place） | 部屋のすみ／高いところ／部屋のまんなかにいる | **ポーズではなく位置** | 行動の**前**に置かれ文脈を作る。絵は同じ descriptor から `PLACE_POSITIONS`（`drawScene.ts`）で位置を決めるので、**文と絵が必ず同じ場所を指す**（**EP-4.02b 実装済**） | — |

✅ **6語彙すべてが別の絵を持つ（EP-4.02c）。** 姿勢が見える5つは互いに異なるスプライトで、`out_of_sight` は描かない。
**この「潰れなさ」は回帰テストで見張っている**（`sprites.test.ts`: 5語彙のスプライトキーが重複ゼロであること）。
語彙を増やしたら、絵も同時に増やす——同じ絵に倒すと、観察文が違っても絵が同じになり、
`EP-4.02b` で手に入れた「〈場所〉で〈行動〉」の文脈が絵の側で失われる。

#### 今後追加される語彙に対応するポーズ（先行定義・B-B 残り / B-D）

| 追加語彙 | ポーズ |

## 6. 素材パーツ表（Step 4）

### 6.1 スタイルロック（全プロンプト共通の接頭辞）

**すべての生成に、必ずこの接頭辞を付ける。** 統一感はここで決まる。

```
soft hand-drawn children's picture-book illustration, gentle rounded shapes,
even dark-brown outline (never black), flat colors with a single soft warm shadow,
warm cream palette (base #f7efe0), light pine wood tones (#d8b98f),
soft natural daylight from the left, calm and quiet, Japanese cat shelter room,
no gradients on large areas, no gloss, no rim light, no texture noise
```

**共通ネガティブ:**

```
--no text, watermark, logo, signature, harsh contrast, neon, glitter, sparkles,
anime big eyes, photorealism, 3D render, drop shadow, vignette, dark shadows,
sad expression, cage, chain, tears, clutter
```

### 6.2 背景・部屋（ラスター・非透過・**最重要 / 最初に作る**）

構図固定（§1.4）ゆえに、**背景はたった2枚で全編を賄える**。ここに一番時間をかける。

| id | 内容 |
|---|---|
| `room-day` | 昼の部屋（窓からの自然光） |
| `room-night` | 夜の部屋（低い灯り・窓の外だけ寒色） |

> **完成形プロンプトと座標定義は [docs/16a](docs/16a-ASSET-PROMPTS.md) §6。**

⚠️ **構図は自由に描けない。** [src/content/environment.ts](src/content/environment.ts) の3つの Zone 属性が、そのまま構図を決める:

| Zone | 家具 | 属性が要求すること | 絵での位置 |
|---|---|---|---|
| `zone.vantage` | キャットタワー | light **0.8**（最明）・humanDistance 0.5 | 窓の右隣・高所 |
| `zone.open_floor` | クッション | humanDistance **0.2**（人に最も近い）・traffic 高 | 手前中央の床 |
| `zone.refuge` | 隠れ箱 | light **0.3**（最暗）・humanDistance **0.6**（最遠） | 右奥の隅・陰 |

**光・距離・静けさがデータと絵で食い違うと、プレイヤーの推論が壊れる。**
「暗くて静かな隅にいる」という観察が絵では明るい窓辺だった——これは `docs/18` B-B（文脈つき観察）を無効化する。

⚠️ **必ず「猫なし」で生成する。** 猫は SVG で上に載せる（§7.1）。
⚠️ 中央床を広く空ける——**猫が動ける余白**が要る（`docs/16a` §6.2 の座標表）。

## 7. 組み立て（Step 6）

### 7.1 レイヤ構成

```
┌─ Canvas 2D (Scene.tsx / drawScene.ts) ────────────┐
│                                                    │
│  z0  背景ラスター      room-day.webp / room-night  │
│  z1  家具ラスター      shelf / box / cushion       │  ← Zone 定義と座標を共有
│  z2  痕跡ラスター      不在時のみ・1つだけ           │
│  z3  猫 SVG（合成）    Appearance × Pose           │  ← 位置は Zone に従う
│  z4  光のオーバーレイ   light-pool / night-lamp     │  ← 乗算/加算・薄く
│                                                    │
└────────────────────────────────────────────────────┘
     ↑ ADR-001 の Canvas 2D 構成のまま。PixiJS は不要（Pillar 6）
```

**猫が SVG コード合成である理由**（§0 の再掲＋根拠）:

| | ラスター（画像生成AI） | **SVG パーツ合成** |
|---|---|---|
| 個体差 400通り | 全組合せの生成が非現実的 | **seed から自由に生成** |
| ポーズ 6種 × 個体 | 掛け算で破綻 | パーツ差し替えのみ |
| 容量 | 個体×ポーズ分 | **ほぼゼロ** |
| 決定論（G-3） | 事前生成に固定 | **完全に決定論的** |
| 絵の質 | 高い | 設計次第（§3 のガイドで担保） |

→ `docs/18` B-A（毎回違う猫）が全ブロックの前提である以上、**猫だけは合成でなければならない**。

### 7.2 実装の受け皿（既存コードへの接続）

| 対象 | 現状 | 必要な変更 |
|---|---|---|
| [sprites.ts](src/presentation/sprites.ts) | 3ポーズ固定・単色 `#8a8177`・data URI | **Appearance × Pose の合成関数**へ。7レイヤをパラメータ化 |
| [drawScene.ts](src/presentation/drawScene.ts) | 幾何プレースホルダ | 背景/家具ラスターの `drawImage`、猫の**Zone 座標配置**、光オーバーレイ |
| [theme.ts](src/presentation/theme.ts) | UI + SceneColors | §2.1.2 / §2.1.3 の**木・光トークンを追加** |
| `assets/`（新規） | — | 背景2枚・小物8点・痕跡4点。Vite の asset import（ハッシュ付きURL・CSP `self` で安全） |

⚠️ **層境界は不変**（ADR-001 / 憲章 I-1）: これらはすべて L4 内の変更。Appearance は L4 に渡す時点で**数値ではなく描画パラメータ**であること。CatProfile（気質）は**絶対に L4 に渡さない**（§3.5）。

### 7.3 容量・配信

| 項目 | 見積 |
|---|---|
| 背景 ×2（WebP 1280×960） | 約 120 KB |
| 小物・痕跡 ×12（WebP 512） | 約 90 KB |
| UIアイコン（SVG インライン） | 約 4 KB |
| 猫（コード） | 0 KB |
| **合計** | **約 214 KB** |

憲章 §9.7（インストール不要・通信断耐性）の範囲内。背景は Preload、小物は Lazy（B4 §12.3 のコード分割方針に合わせる）。

| 段階 | 担当 | 成果物 |
